# deployment-profiles-v2 — доделки общих сервисов после приёмки v1

Ран `deployment-profiles-v2`. Ветка задач — `dev`. Продолжение [deployment-profiles-v1](deployment-profiles-v1.md):
цели владельца, приёмка сборок A/B/C и правила выпуска те же.

## Почему второй прогон

Сверка принятых задач v1 с планом (2026-10-19):

- **C04 (Kanban)** почти не сделана: адаптер реестра не подключён, нет `/_sislexa/enter`, `core_id` в данных, делегирования,
  API реестра и учёта.
- **C07 (Web Reader) и C09 (Image Studio)** не принимают браузерный `GET /_sislexa/enter` из B01 и обходят делегирование
  (grant из тела запроса или учётные данные сервиса с именем пользователя в аргументах).
- **C06 (Identity)**: один процесс обслуживает один realm, нет API реестра, отключена очистка данных пользователя.
- **C03 (Make)** остановилась: в B01 не было полномочий делегирования. Закрыто задачей B02 (Core #742): ответ погашения
  тикета несёт `delegation { token, expiresAt }`, сессия сервиса живёт 8 ч, `CoreDelegationClient(registry, session)`
  отправляет `x-sislexa-delegation` вместе с учётными данными сервиса.
- **C08 (Playwright Reader)** и **C05 (Kanban, профили и выкатка)** не запускались.

Все сервисы на `dev` уже закрепили Shared 0.1.39 и component-runtime 1.2.0. Песочница модели не даёт запускать `npm` и
`git` (EPERM): гейт прогоняет интегратор, модель не записывает отчёты песочницы в репозиторий. Автоприёмка выключена,
каждую задачу принимает оператор по пунктам.
