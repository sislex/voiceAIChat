# Карточка задачи: круги улучшений

Цикл над открытой карточкой (`TaskModal` и её панели). Один круг: забрать из
`main` → 20 предложений → выполнить → витрина + юнит-тесты + браузер → чинить до
зелёного → KB → коммит и push в `work2`.

Промпт для запуска цикла — в конце файла.

## Круг 1 — 2026-08-31

Базовая линия, снятая перед кругом: открытие карточки задачи делает
**3–4 запроса до того, как пользователь что-либо открыл**:
`GET tasks/:id` (детали), `listTaskImprovements`, `getTaskKbUsage`,
`getTaskReport` (у завершённого рана) и загрузки секции «Дизайн» — при том, что
«Улучшения», «Ход выполнения» и «Дизайн» могут не открываться вовсе.

### A. Скорость загрузки и работа с данными

1. **Улучшения — не при каждом открытии.** `listTaskImprovements` запрашивать
   только когда у задачи вообще был ран (`ciSummary` или `latestRunResult`).
   *Критерий:* тест «карточка в бэклоге не зовёт `listTaskImprovements`».
2. **KB-использование — по вкладке.** `getTaskKbUsage` грузить, только когда
   активна «Ход выполнения». *Критерий:* тест на отсутствие вызова на «Общем».
3. **Отчёт по рану — по вкладке.** То же для `getTaskReport`.
4. **Секция «Дизайн» — по вкладке.** `TaskDesigns` монтировать, только когда
   активна «Общее» (карточка с активным раном открывается на «Ленте рана»).
5. **QA-панели не грузятся при открытии карточки.** `ComponentQaPanel`,
   `QaStageRunPanel`, `ManualQaPanel` и `FeaturePreviewSection` рендерятся без
   всякой проверки активной вкладки и грузят себя при показе карточки.
   Отложить до первого открытия своей вкладки. Merge, подготовку и ленту рана
   **не трогаем**: они намеренно размонтируются (свежий снимок машин при
   возврате, живые подписки). *Критерий:* тест на отсутствие вызова до открытия.
6. **`loadFullTask` не перезапрашивает то же самое.** Пропускать запрос, если
   детали этой задачи уже загружены и `updatedAt` не изменился.

### B. Переиспользуемые компоненты (каждый — с DOM-тестом и сторис)

7. **`PropertyRow`** — строка «подпись | значение» правой колонки. Сейчас
   разметка повторяется девять раз руками.
8. **`SectionHeader`** — заголовок секции с текстовым действием справа
   (описание, критерии, подзадачи, активность — четыре копии).
9. **`ChipList`** — чипы с удалением и полем добавления. Метки и навыки сейчас
   скопированы друг у друга слово в слово.
10. **`TaskActivity`** — секция «Активность» отдельным компонентом (сейчас
    вкладка «Общее» живёт внутри `TaskModal` на 1400 строк).
11. **`TaskSubtasks`** — секция подзадач отдельным компонентом.

### C. Интерфейс

12. Фокус-кольцо вкладки не должно перекрывать её подчёркивание и текст.
13. Обрезанные значения правой колонки (длинное имя колонки в «Статусе»,
    родитель) показывают полный текст в `title`.
14. Пустые «Стори-поинты» и «Срок» показывают приглушённое «—», как «Автор», а
    не выглядят как поле, куда забыли что-то ввести.
15. В тёмной теме подложка колонки свойств отличима от фона карточки.
16. Секция «Активность» без событий не рисует пустой заголовок.

### D. Мобильный интерфейс

17. Текстовые действия секций (`.task-section-action`) — цель нажатия ≥ 40px.
18. Полоса вкладок на телефоне останавливается на вкладке целиком
    (`scroll-snap`), а не посередине подписи.
19. Форма добавления подзадачи на телефоне — поле и кнопки во всю ширину.
20. Правая колонка на телефоне не даёт горизонтального выезда при длинном имени
    проекта и длинных чипах.

## Круг 2 — 2026-08-31

Осталось с круга 1: внутренности QA- и merge-панелей всё ещё говорят своим
языком (`<header><h3>` + `.qa-status`, `dl`, голые `ul` и `pre`), а главный чанк
`index-` весит 1 288 КБ.

### A. Панели QA и Merge на общий язык

1. `ComponentQaPanel`: `PanelHeading` + `StatusPill` вместо `<header><h3>` и `.qa-status`.
2. `ComponentQaPanel`: `MetricGrid` (ветка / SHA / попытка) вместо `dl.component-qa-meta`.
3. `ComponentQaPanel`: счёт сценариев — `QaScore` («12 из 12 прошли» с полосой).
4. `ComponentQaPanel`: сценарии — `ResultTable` («проверка | результат»).
5. `ComponentQaPanel`: команды и потоковый лог — `FeedItem` + `FeedLog`.
6. `QaStageRunPanel`: `PanelHeading` + `StatusPill` + `ProgressTrack` шага + `ResultTable`.
7. `MergePanel`: `PanelHeading` + `BranchFlow` (ветка → main) + `StepList`.

### B. Новые примитивы ui-kit (каждый — с DOM-тестом и сторис)

8. **`QaScore`** — «N из M прошли» с полосой и тоном.
9. **`ResultTable`** — таблица «проверка | результат», результат окрашен тоном.
10. **`GateList`** — список проверок гейта: значок, название, деталь, вердикт.
11. **`BranchFlow`** — «ветка → ветка» с подписью об изменениях.

### C. Разгрузка главного чанка

12. `MakePane` (2132 строки) — ленивый чанк по образцу `SessionsDialogHost`/`UsersAdmin`.
13. `PromptBuilder` — ленивый: AI-помощник открывается по палочке, а не сразу.
14. Замерить факт и **опустить** планку `index-` до него (сейчас она поднята под мерж).

### D. Интерфейс

15. Статус во всех вкладках карточки — один `StatusPill`; `.qa-status`, `.merge-chip`,
    `.merge-badge` в карточке больше не заводим.
16. «Запуск недоступен» в Component QA — `ErrorState compact` с причинами, а не
    голый `<strong>` со списком.
17. «Стадия недоступна» / «Component QA недоступен» — `EmptyState`, а не текст в `section`.

### E. Мобильный интерфейс

18. `ResultTable` на телефоне — строка в две строки, а не две сжатые колонки.
19. Сводка и счёт в QA-панелях не дают горизонтального выезда на 390px.
20. Кнопки действий QA-панелей на телефоне — во всю ширину и от 44px.

## Круг 3 — 2026-08-31

Осталось с круга 2: `Automated QA` (`GenericQaStageRunPanel`) не переведён на
общий язык — и там же нашёлся дефект: пользователю показывался сырой
`run.status` («running», «gate_failed»).

### A. Automated QA и общий этап на общий язык

1. Сырой `run.status` → `StatusPill` с русской подписью `QA_STAGE_RUN_STATUS_LABELS`.
2. Шапка панели с действиями → `PanelHeading` вместо `<h3>` + кнопок в ряд.
3. Абзац «статус · попытка · ветка · SHA» → `MetricGrid`.
4. Безымянный `<progress>` → `ProgressTrack` с `label` (читалка объявляла
   «индикатор» без «чего»).
5. `run.gateReasons` → `GateList` — первый потребитель примитива из круга 2.
6. Потоковая лента из `div`-ов в `.ci-log` → `FeedItem` + `FeedLog`: имя области,
   прокрутка с клавиатуры, тёмный лог в обеих темах.
7. История попыток в Component QA печатала сырой `item.status` — тоже дефект.

### B. Новый примитив ui-kit

8. **`AttemptHistory`** — «История попыток» была скопирована в четырёх панелях, и
   каждая копия расходилась: где-то `ol` с сырым статусом, где-то кнопка выбора,
   где-то без даты. Выбор попытки — `aria-current`, а не `aria-selected`.

### C. Данные и API

9. **`lib/usePolling`**: опрос QA-панелей встаёт по `document.hidden` — карточка,
   оставленная открытой, стучала в сервер каждые 1,5–2 с и в фоновой вкладке.
10. Возврат на вкладку сразу догоняет состояние одним внеплановым запросом.
11. Индексы SQLite под запросы карточки — **проверено, недостающих нет**: у всех
    task-таблиц есть `(task_id, created_at DESC)`, у улучшений —
    `(task_id, status, updated_at DESC)`. Изменений не потребовалось.

### D. Сторожи против сырых статусов

12. `components/qa/qaLabels.test.ts` — панели не выводят `status` в разметку без
    подписи (`data-status={…}` законен, сравнения и индексация тоже).
13. Тот же сторож — английский статус внутри русского литерала разметки.

### E. Интерфейс и мобильный

14. Действия этапа в шапке панели; на телефоне уходят под заголовок во всю ширину.
15. Форма ответа модели: поле во всю ширину, 16px, кнопка от 44px.
16. `AttemptHistory` на 390px — строка в две строки, время не уезжает под номер.
17. Лог этапа тёмный в обеих темах (через `FeedLog`), а не `.ci-log` из `div`-ов.
18. Сторож стилей пополнен классами `qa-stage-*` и `vc-attempts*`.
19. Сторис `UI/Run panels`: «История попыток» и «Automated QA целиком».
20. **Регрессия из круга 1, найденная пользователем**: во вкладках карточки не
    было вертикального скролла — `flex-wrap: wrap` у `.jmodal-panels` уводил
    каждую панель на свою строку, и `overflow: auto` было нечего ограничивать.
    Починено, закреплено сторожем и проверено в браузере.

## Промпт для запуска цикла

```
Приведи открытую карточку задачи (TaskModal в packages/ui/src/components/kanban/)
к макету http://89.125.68.35:8787/p/8d2a107ea0e9445fb80524c3bcae7b49/index.html:
структуру повторяй точно, а цвета бери из существующих токенов app.css — тёмная
тема и contrast.test.ts должны остаться зелёными.

Затем гоняй цикл, пока я не скажу «стоп». Каждый круг:
1. git fetch origin && git merge origin/main (worktree work2, без git stash).
2. Предложи 20 улучшений этой страницы и запиши их в docs/plans/task-card-rounds.md
   разделом «Круг N», по темам: скорость загрузки, переиспользуемые UI-компоненты
   (каждый — с .dom.test.tsx и сториз), скорость API, оптимизация загрузки данных,
   интерфейс, мобильный интерфейс. У каждого пункта — проверяемый критерий.
3. Выполни их; тест пишется в том же шаге, что и код.
4. Проверь: витрину (npm run build:storybook + скриншоты историй Kanban/TaskModal
   через Chrome MCP в светлой и тёмной теме, 1440/820/390px), юнит-тесты
   (npm run gate), бюджет чанков (node scripts/frontend-quality.mjs --bundle) и
   живое приложение в браузере (dev на своих портах PORT=8799 VC_WEB_PORT=5299
   VC_RECORDER_PORT=5300, не на 8787; смотри консоль и сеть).
5. Есть ошибки — чини до зелёного и перепроверяй тем же гейтом. Гейт зелёный по
   коду возврата, а не по отсутствию строк в выводе.
6. /kb-update — правки docs/kb + запись журнала + npm run kb:index.
7. Один conventional-коммит круга (код + KB) в work2 и git push origin work2.
8. Короткий отчёт: что вошло, что отложено, цифры. Дальше — следующий круг без
   моего подтверждения.
```
