# reliability-v2 — длинные чаты, VPN-доступ окружений и подготовка без базы знаний

Ран `reliability-v2` закрывает три задачи доски с высоким приоритетом:

- «Чат: виртуализация ленты — длинные чаты медленно открываются» и «Устранить зависания Make на длинных
  чатах». Замер 2026-10-05 на разговоре Make `54254abe-491c-4d7d-9d5c-03ec7b6771ad`: 360 сообщений,
  около 11 тыс. DOM-узлов, вкладка десятки секунд занимает CPU при открытии. Каждое нажатие в поле
  ввода стоило ~440 мс; это исправлено в Core UI 1.5.1 (ядро 0.1.406). Осталась первая отрисовка всей
  ленты и перерисовки старых сообщений при стриминге.
- «Окружения: удаление u04-check не сняло VPN-доступ». Повтор `vpn-grant/remove` отвечает
  `RPC_HTTP_500`, ядро не сообщает причину. Тег `tag:chatai-env-d4734cda779007dd6c8a2efe` остался на
  MacBook, M1 и s1. В `VpnService.environmentGrant` при снятии политика без `tagOwners` тега
  записывается раньше, чем тег снимается с устройств: Tailscale может отклонить политику, пока тег
  стоит на устройствах, и не позволяет оставить tagged-устройство без тегов.
- «Kanban: подготовка задачи в проекте без базы знаний всегда падает (missing_knowledge_source)».
  Проект Kanban «Make» (sislex/make): 4 попытки подготовки остановились на проверке готовности.

Этап 0 — контракты и ядро, этап 1 — потребители.
