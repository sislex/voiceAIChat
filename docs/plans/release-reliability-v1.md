## Решения

- **Тесты не опираются на короткие фиксированные таймауты.** Ожидание событий — промисы по сообщениям с бюджетом 30 с, внешние
  команды в тестах — без 15-секундного предела (или 120 с); при падении тест печатает `code`, `signal`, `stderr`, `stdout`.
- **`gate:all` сообщает упавшие файлы.** `full-gate.mjs` собирает упавшие тестовые файлы (как `runTests` через
  `GATE_TEST_REPORT`) и печатает последней строкой `GATE-FAILED-TESTS: <json-массив путей>` и `GATE-FAILED-STAGE: <имя>`.
- **Регрессия релиза повторяет упавшие файлы один раз.** Если `testCommand` упал и `GATE-FAILED-TESTS` не пуст (≤ 20 файлов),
  Kanban запускает `npm run test:files -- <файлы>`; зелёный повтор — регрессия пройдена, в журнале шага — «повтор прошёл: …».
  Релиз хранит `failedTests: string[]` и `failureTail` (последние 80 строк без ANSI); `releaseFailureSummary` не берёт строки
  YAML/TAP и при наличии `failedTests` пишет «N упавших тестов: a, b».
- **Браузер Playwright ставится сам.** `scripts/ensure-playwright-browser.mjs` (`globalSetup` в `e2e/vitest.config.ts`): если
  нет исполняемого файла headless-оболочки Chromium — один раз `npx playwright install chromium` (с `PLAYWRIGHT_BROWSERS_PATH`);
  при `VC_PLAYWRIGHT_OFFLINE=1` или `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` — понятная ошибка без загрузки.
- **Восстановление процессов стенда не разрушает данные.** Ошибка восстановления оставляет запись реестра и рабочую копию,
  процесс получает состояние `failed` и повторы с паузой (3 попытки, бюджет готовности при восстановлении 300 с); рабочая копия
  удаляется только явной остановкой или заменой.
- **Коды ошибок стенда:** `stand_fetch_failed`, `stand_git_timeout`, `stand_worktree_dirty`, `stand_agent_timeout` (504),
  `machine_unavailable` (409), `machine_offline` (409), `storybook_port_busy`, `storybook_no_free_port`; Storybook-маршруты
  сохраняют `statusCode`/код ошибок прокси стенда; сбой запуска — поле `errorCode` (`storybook_exit_nonzero`,
  `storybook_exited_before_ready`, `pty_error`, `storybook_port_busy`). Make показывает RU/EN текст на каждый код.
- **Юниты хоста — одним скриптом.** `scripts/apply-host-units.sh` (root, идемпотентно) пишет `delivery-control-firewall.service`
  и drop-in `firewall.conf`, `daemon-reload`, `enable`, `restart` службы правил, не трогая основной юнит; `install-host.sh`
  вызывает его; выкат оператора вызывает его после переключения `current`.
