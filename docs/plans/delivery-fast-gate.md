# Быстрый гейт задач и фоновый полный гейт `main`

План `delivery-fast-gate`. Задача воркера сдаётся по быстрому гейту — typecheck и сборка
изменённого приложения плюс тесты, относящиеся к изменённым файлам. Полный набор тестов идёт
фоном на свежем `main` и на регрессии релиза. Упавшие тесты после исправления прогоняются
первыми: снова упали — сразу следующее исправление, прошли — затем быстрый гейт целиком.

## Решение владельца (2026-10-04)

1. Гейт задачи — быстрый: typecheck затронутых пакетов, сборка изменённого приложения, тесты
   изменённых файлов и тесты модулей, которые они затрагивают. После него мерж.
2. Полный гейт — фоновая проверка `main` координатором (после нескольких мержей или по таймеру)
   и регрессия релиза. Падение создаёт приоритетную задачу-исправление.
3. Исправление: сначала упавшие тесты; упали снова — сразу новое исправление, не дожидаясь
   остальных; прошли — быстрый гейт целиком (для задачи-исправления после регрессии — затем
   полный гейт).

## Устройство

- **Знание о раннерах — в репозитории.** Каждый репозиторий даёт два скрипта:
  - `npm run gate:quick -- --base <sha>` — быстрый гейт по diff от `<sha>`; при падении печатает
    строку `GATE-FAILED-TESTS: <json>` — массив путей тестовых файлов от корня репозитория;
  - `npm run test:files -- <файл> [<файл> …]` — прогон только этих тестовых файлов тем же
    раннером (vitest, node:test, python unittest), с той же строкой при падении.
  Неизвестное изменение (корневой конфиг, lock-файл) делает `gate:quick` полным гейтом.
- **Воркер Delivery Control** не разбирает вывод раннеров: читает `GATE-FAILED-TESTS`, после
  исправления запускает `test:files` по этим файлам, затем гейт задачи. Нет строки или файлов —
  как сейчас, весь гейт.
- **Фоновый полный гейт.** Координатор держит для каждого репозитория активных прогонов
  счётчик мержей. После 3 мержей или через 60 минут после первого непроверенного мержа он
  создаёт служебную задачу `main-check` (без модели: только полный гейт на голове `main`) с
  низким приоритетом. Падение порождает задачу `regression` с приоритетом 0: база — та же голова,
  описание — команда, код выхода и `GATE-FAILED-TESTS`, гейт — `test:files` по упавшим, затем
  быстрый и полный гейт.

## Задачи

Таблица задач рана `delivery-fast-gate-v1` — в [delivery-fast-gate-v1.md](delivery-fast-gate-v1.md).

Задачи интегратора (Claude, вне манифеста):

- **U01: выкат и переключение.** Мерж B01→C01→C02 (delivery-control) и C03–C07 по репозиториям;
  выкат координатора и воркеров; новые задачи прогонов настраиваются с
  `gate: npm run gate:quick -- --base <base>` и `rerun: npm run test:files --`; проверка на
  настоящей задаче: падение теста → исправление → первыми идут упавшие файлы; фоновая
  `main-check` срабатывает после мержей, её падение создаёт `regression`.

## Готово, когда

- задача сдаётся по быстрому гейту, полный набор её не задерживает;
- после исправления первыми идут упавшие тесты, повторное падение сразу уходит в исправление;
- поломка `main`, которую быстрый гейт не увидел, ловится фоновой проверкой за час и
  превращается в приоритетную задачу.

## Риски

- Тест, сломанный правкой без прямой связи с изменёнными файлами, проживёт в `main` до фоновой
  проверки; задачи, начатые от такого `main`, наследуют поломку до исправления.
- Фоновая проверка занимает воркер на время полного гейта; поэтому низкий приоритет и счётчик
  мержей вместо проверки после каждого.
