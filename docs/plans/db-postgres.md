# Postgres как движок базы — план перевода слоя данных

Живая реализация: `apps/server/src/db/sql/` (адаптер `Sql` над better-sqlite3 и node-postgres),
`apps/server/src/db/repos/<домен>.ts` (асинхронные репозитории, один код на оба движка),
`apps/server/src/db/schemaPg.ts` (DDL Postgres, выводится из SQLite-схемы и проверяется тестом),
`scripts/db-to-postgres.ts` (перенос данных).

## Зачем

Цель — запускать канбан, машины, админку и прочие части приложения на любом сервере, оставив
центральными чат, базу и исполнителей LLM (`docs/plans/make-standalone.md` сделал это для Make —
у него нет таблиц). Всё остальное таблицы имеет, и **SQLite к этому не годится**: это файл, его
нельзя открыть с другого хоста. Значит, «указать в настройках, где лежит база» возможно только
для сетевой базы — Postgres.

Разрез слоя данных (`docs/plans/db-repositories.md`) подготовил почву: владельцы таблиц,
асинхронные порты, PoC `releases` на pglite за тем же портом. Но PoC пошёл путём «вторая реализация
домена на другом движке» — для 6,5 тыс. строк остальных доменов это переписывание с высоким риском
расхождений. Здесь путь другой: **один код репозитория на оба движка** над узким адаптером `Sql`,
а различия диалектов закрываются в одном месте — транслятором SQL и DDL для Postgres.

## Решения

- **Вся база на одном движке**, а не домен за доменом. Кросс-доменные JOIN'ы (`CROSS_READ_BUDGET`)
  остаются работать; сервисы, которые уедут на другие хосты, подключаются к тому же Postgres и
  работают со своими таблицами тем же кодом репозиториев. Переключатель — `VC_DB_URL`
  (`postgres://…`); без него — SQLite, как сейчас. PoC pglite/`VC_DB_RELEASES` снимается.
- **Репозитории становятся асинхронными внутри**: `await this.sql.get/all/run(sql, params)`
  вместо `this.db.prepare(sql).get(...)`. Для SQLite это обёртка над тем же синхронным драйвером
  (сервер и так говорит с данными через async-порты), для Postgres — настоящий await.
- **Транзакции — `await this.sql.transaction(async () => …)`** с AsyncLocalStorage: всё, что
  выполняется внутри колбэка (включая вызовы соседей `this.repos.*`), идёт через соединение
  транзакции; вложенные — через SAVEPOINT. У SQLite одно соединение, поэтому на время открытой
  транзакции остальные запросы ждут (мьютекс) — иначе чужой запрос попал бы внутрь чужой транзакции.
- **Постгресовский DDL выводится из SQLite-схемы** программно (`INTEGER`→`BIGINT` для меток
  времени и счётчиков, `REAL`→`DOUBLE PRECISION`, `AUTOINCREMENT`→`BIGSERIAL`, у каждой таблицы
  явный `rowid BIGSERIAL` — код, которому нужен порядок вставки, не меняется), результат
  зафиксирован в `schemaPg.ts` и сверяется тестом с `schema.ts`, чтобы они не разъехались.
- **Диалект в одном транслятере** (`db/sql/dialect.ts`): `?`→`$n`, `INSERT OR IGNORE`→
  `ON CONFLICT DO NOTHING`, `IFNULL`→`COALESCE`, `MAX(a, b)`/`MIN(a, b)`→`GREATEST`/`LEAST`,
  `LIKE`→`ILIKE` (у SQLite LIKE регистронезависим), `ulower()`→`lower()`, `json_extract(x, '$.k')`→
  `(x::json->>'k')`, `IS ?`→`IS NOT DISTINCT FROM $n`. Что транслятор не берёт — правится в репозитории
  так, чтобы работало на обоих движках. Полнотекстовый поиск сообщений (FTS5) на Postgres — `tsvector`.
- **Миграции существующих SQLite-баз (`migrate()`, 186 ALTER TABLE) остаются SQLite-only**:
  Postgres-база создаётся переносом из SQLite уже в актуальной схеме, поэтому ей нужны только
  будущие миграции — они пишутся сразу для обоих движков.
- **Проверка — тем же набором тестов.** `VC_TEST_DB_URL=postgres://…` заставляет
  `new VoiceChatDb(':memory:')` в тестах открывать свежую схему в Postgres: вся матрица тестов
  сервера (2,2 тыс.) гоняется на втором движке без переписывания.

## Риски
- **Строгий `GROUP BY` Postgres** (у SQLite — нет): 19 запросов пересматриваются по одному.
- **`rowid`**: явный `rowid BIGSERIAL` в DDL закрывает `ORDER BY rowid`/`WHERE rowid = ?`; вставка
  с явным rowid есть только у FTS-триггеров чата, которые на Postgres не нужны.
- **Мьютекс транзакций в SQLite**: если тело транзакции будет ждать внешнее событие, которое само
  ходит в базу из другого контекста, — взаимная блокировка. Тела репозиториев внешнего не ждут
  (они были синхронными); правило записывается в conventions.
- **Производительность**: на SQLite добавляется микрозадача на запрос — при 900 запросах в коде это
  незаметно; циклы с сотнями `run` остаются в одной транзакции.
