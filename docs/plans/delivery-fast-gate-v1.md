# delivery-fast-gate-v1 — задачи рана

Ран `delivery-fast-gate-v1`, план [delivery-fast-gate.md](delivery-fast-gate.md). Здесь только
таблица задач; решения, устройство и задача интегратора U01 — в основном файле. Каждая задача
начинается от свежего `main` своего репозитория.

| B01 | delivery-control | — | Fast-gate contracts per docs/plans/delivery-fast-gate.md «Устройство»: Execution gains optional rerun (argv prefix to which failed test files are appended, e.g. npm run test:files --) with schema validation; a pure parser parseFailedTests(output) that reads the last GATE-FAILED-TESTS: <json> line (array of relative test file paths, deduplicated, at most 200, path rules like allowedPaths, invalid JSON ignored); task kind 'main-check' (gate-only, no model) and 'regression'; unit tests for every parser branch and schema case; update README/operator docs |
| C01 | delivery-control | B01 | Worker failed-first loop per docs/plans/delivery-fast-gate.md «Решение владельца» item 3: when a gate fails, keep parseFailedTests of its output; after a model repair, if the task has rerun and failed files are known, run rerun + files first; on failure feed that output to the next repair round at once (counts as a repair round), on success run the task gates in order; without rerun or files keep today's behaviour; gate-only tasks of kind main-check run their gates without a model and report pass/fail with the GATE-FAILED-TESTS list; tests with fake gate commands for first-run failure, rerun failing again, rerun passing then gate failing, no trailer, and a main-check task |
| C02 | delivery-control | B01, C01 | Background full gate of main per docs/plans/delivery-fast-gate.md «Устройство»: the coordinator counts verified merges per repository of active runs and creates a main-check task (priority 90, base = the main head the coordinator resolves through its source adapter, gate = the repository full gate configured per repository in the run or a coordinator default) after 3 merges or 60 minutes after the first unchecked merge; a failed main-check creates a regression task (priority 0, kind regression, base = that head, description with command, exit code and failed test files, gate = rerun files then gate:quick then the full gate, allowedPaths = whole repository) once per head; a passing check resets the counter; tests in the coordinator store for counting, timing, deduplication per head, failure to regression and success reset; update operator docs |
| C03 | Core | — | Fast gate scripts in Core per docs/plans/delivery-fast-gate.md «Устройство»: npm run gate:quick -- --base <sha> reuses scripts/application-gate.mjs planning but for each selected application runs typecheck, build when present, and vitest only for changed test files plus tests related to changed source files (vitest related with the changed files of that workspace), contracts and tooling likewise; unknown root/config/lock changes fall back to gate:all; npm run test:files -- <files> maps repository-relative test files to their workspace and runs them with that workspace runner (vitest or node:test for tooling); both print GATE-FAILED-TESTS: <json> with repository-relative failed test files on failure; tests for planning and file mapping; update AGENTS.md wording only if needed and docs/kb/testing-operations.md with the KB workflow |
