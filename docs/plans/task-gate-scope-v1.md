# task-gate-scope-v1 — гейт задачи проверяет ближайшие тесты, а не всё замыкание

Ран `task-gate-scope-v1`. Ветка задач — `dev`.

Гейт задачи в ядре, Kanban, Core UI и Make выбирает тесты по транзитивному замыканию импортов
(`vitest related`). Любая правка общего модуля (контракт shared, схема БД, `server.ts`) выбирает сотни
тестов и упирается в лимит владельца «не более 100 тестов» даже когда тесты идут секунды
(ядро — 154 теста за 2 с, Kanban — почти весь сервер); задачи падают и идут через ручную интеграцию.
В Delivery Control это уже исправлено (#172): ближайшие тесты, широкое влияние — в полный гейт перевода.

| B01 | Core | — | The task gate (`npm run gate:task -- --base <sha>`) must check only the changed module within the owner budget (at most 100 tests and 60 seconds) instead of the transitive import closure. Select, in this order: (1) changed test files; (2) test files named after a changed source module (`x.ts` -> `x.test.ts` / `x.dom.test.tsx` in the same package); (3) the other test files that import a changed file directly, only when there are at most 10 of them; when there are more, do not run them and print `GATE-TASK-DEFERRED: <n> direct importer file(s) left to the promotion gate`; never use the transitive closure or `vitest related` for the task gate; keep typecheck of the changed packages; run the selected files in parallel (up to 4 workers); keep the existing output contract (`GATE-TASK-CASE`, `GATE-TASK-SLOW`, `GATE-TASK: tests=<n> seconds=<s>`, exit 2 on budget breach) and documentation-only changes; the full gate at dev → main promotion is unchanged. Tests: selection for a changed module with its own test, a module with more than 10 importers (deferred, reported), a changed test file, a docs-only change; update the testing topic of docs/kb. Delivery Control already works this way (sislex/delivery-control scripts/affected-tests.mjs taskOnly). |
