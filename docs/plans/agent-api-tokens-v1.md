# agent-api-tokens-v1 — токены доступа к API для стороннего агента

Ран `agent-api-tokens-v1`. Ветка задач — `dev`. Задачи выполняют воркеры MacBook (M2); M1 выключен.

## Что случилось

Владелец 2026-10-16 поручил сделать механизм для стороннего агента (например, оператора Claude): получить токен и с ним
через API делать всё, что доступно в интерфейсе, — управлять канбаном, карточками, настройками проектов — и читать
любую информацию. Сегодня это возможно только из браузерной сессии владельца (cookie `vc_session` + заголовок
`x-vc-csrf`), а токены интеграции `sit_…` ограничены проектом и тремя scope `/integrations/v1`.

Разбор кода показал, что `/api/*` уже принимает заголовок `Authorization` с токеном сессии (схема Bearer) и для такого запроса CSRF не
проверяется (`apps/server/src/users/auth.ts` в Identity: `authenticate` берёт токен из `bearer(req)`, CSRF — только при
`viaCookie`). Сервис доски получает те же заголовки через прокси ядра и переспрашивает `POST /internal/whoami`, `/ws`
принимает токен параметром запроса `token`. Значит, токен агента — это долгоживущая именованная сессия пользователя вида `api`, выпущенная и
отзываемая через API и интерфейс «Сессии и устройства». Сессиями владеет Identity (`sislex/identity`, пакет
`@sislexa/identity`, в Core и сервисе доски закреплён архивом `vendor/sislexa-identity-<версия>-<sha>.tgz`).

Целевое поведение:

- `POST /api/session/api-tokens { name, ttlDays?, access? }` из обычной сессии пользователя → `{ token, item }`; токен
  показывается один раз. `access: 'full' | 'read'` — токен `read` допускает только GET/HEAD/OPTIONS (иначе 403
  `read_only_token`). Токен не может выпускать токены (403 `api_token_forbidden`). Срок — `ttlDays` 1…3650, по
  умолчанию 365; срок не продлевается активностью.
- `GET /api/session/api-tokens` → `{ tokens: ApiTokenInfo[] }` свои; `DELETE /api/session/api-tokens/:sid` — отзыв.
  Администратор (`users:manage`) с `?user=<логин>` видит, выпускает и отзывает токены любого пользователя — так
  оператор получает токен служебного пользователя без входа под ним.
- Токены не показываются в списке устройств, не получают cookie, но гасятся «выходом со всех устройств» и «паникой».
- В «Сессии и устройства» (`@sislexa/identity/sessions-app`) появляется раздел «API-токены»: список, выпуск с показом
  токена один раз, отзыв. Core UI подключает его через мост сессии.
- Core закрепляет новую версию Identity, объявляет пути в `REST` контракта и описывает в БЗ, как стороннему агенту
  работать через API: заголовок `Authorization` (схема Bearer), без CSRF, параметр запроса `token` у `/ws`, карта маршрутов (`REST` в
  `packages/shared/src/protocol.ts`, маршруты сервиса доски), ограничения.
