# kb-service-v3 — знания модулей уходят из ядра в сами модули

Ран `kb-service-v3`. Ветка задач — `dev`. Продолжение `kb-service-v2`.

Владелец, 2026-10-07: в ядре не должно быть данных о коде модулей — за ними ходят в базы знаний
самих модулей. Ссылки оставляем, если они ускоряют и удешевляют работу: только на уровне модуля
(`<module>:README.md`, оглавление базы модуля), без фактов и без ссылок на отдельные разделы.

## Что видно сейчас

Карта покрытия (`kb-service-v2`, 2026-10-07) сверила 265 разделов тем ядра с собственными темами
модулей: полностью покрыты 7, частично — 108, не покрыты — 104, остаются в ядре по назначению — 46.
Темы Core UI — выжимки по ~20 строк, интерфейс доски и карточек задач не описан нигде, у UI Kit и
Image Studio нет базы знаний. В Kanban и Core UI лежат дословные копии тем ядра (`*-reference.md`),
которые никто не поддерживает.

Интегратор разложил по модулям 222 раздела (без 46 разделов ядра), каждый ровно в одном модуле:
`docs/kb/import/core-sections*.md` в `dev` каждого репозитория (Core `origin/dev` 287cdab3). Полная
таблица «раздел → модуль → что остаётся в ядре» — [kb-service-v3-assignment.md](kb-service-v3-assignment.md).

## Решения

1. «Сначала копия у владельца»: этап 0 переносит знания в модули, этап 1 удаляет их из ядра —
   только после приёмки всех задач этапа 0.
2. Модуль сверяет каждый факт со своим кодом: устаревшее исправляет или выбрасывает с записью в журнале.
3. В ядре остаются только разделы владельца `core` и «что остаётся в ядре» у смешанных разделов.
   Тема, целиком принадлежащая модулю, заменяется заглушкой из нескольких строк со ссылкой на
   `<module>:README.md`; у смешанной темы — одна строка «Подробности модуля: `<module>:README.md`».
4. Темы ядра об LLM Runner и речи (`llm.md`, `stt-*.md`, `tts-runner.md`) описывают в основном
   интеграцию в сервере ядра — следующий прогон.
