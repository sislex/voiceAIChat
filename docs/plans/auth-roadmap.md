# Логин и регистрация — roadmap

Статусы: ✅ сделано · ⏸ ждёт внешнего ресурса (SMTP, OAuth-клиенты) · ✗ пропущено (причина в строке).
Выполняется сразу после `make-roadmap-4.md`, по тем же правилам (гейт, стенд :8799, KB + коммит, релиз каждые 5 пунктов).
Текущее состояние: пароли — scrypt с солью (`users/passwords.ts`), вход по имени+паролю, пользователей создаёт админ, саморегистрации нет, токен сессии в localStorage.

## Безопасность входа
| № | Пункт | Статус |
|---|---|---|
| 1 | Rate-limit `POST /api/session/login`: 10 попыток / 10 мин по IP и по имени, 429 + Retry-After | ✅ `SlidingWindowLimiter` ×2 в `users/auth.ts` (по IP и по имени, скользящее окно), 429 + `Retry-After` + `retryAfterSec` в теле |
| 2 | Политика пароля: запрет пустого, минимум 10 символов; проверка по утечкам (HIBP k-anonymity) — опционально | ✅ `checkPasswordPolicy` (`@shared/passwordPolicy`: пустой/короче 10/повтор/частый/содержит логин) на создании пользователя → 400; HIBP k-anonymity при `VC_HIBP_CHECK=1` (fail-open, 3 с) |
| 3 | Блокировка аккаунта после N неудач (счётчик в БД), уведомление админу | ✅ колонки `failed_logins/locked_until/lock_reason`: 5 подряд → замок 15 мин (423 + Retry-After), 10 → `blocked` с причиной `auto`; админка показывает «замок до…»/«заблокирован автоматически», в лог сервера — warn; разблокировка снимает всё |
| 4 | Сессии с TTL и отзывом: таблица сессий (устройство, IP, last seen), «выйти везде», список в админке | ✅ таблица `sessions` (sid из токена, UA/IP/last_seen/expires 30 дней, отзыв), `/api/session/list|logout-all|:sid`, админ `GET users/:name/sessions`, `DELETE sessions/:sid`; диалог «Сессии и устройства» в меню аккаунта, раздел «Сессии» в админке. Развитие (2026-08-30): переносимые пакеты `@voicechat/sessions-core` + `@voicechat/sessions-app`, метаданные устройства и гео, доверенные устройства (пропуск 2FA), лимит сессий и авто-отзыв брошенных, живые кадры `sessions.update`/`session.revoked`, e2e `npm run e2e:sessions` |
| 5 | Токен в HttpOnly-cookie + CSRF-токен для мутаций вместо localStorage | ✅ login ставит `vc_session` (HttpOnly, SameSite=Strict, Secure за https) и `vc_csrf`; мутации по cookie требуют `x-vc-csrf`; WS принимает cookie при upgrade; web хранит Bearer только в памяти, старый localStorage-токен переносится `POST /api/session/cookie` и удаляется; Bearer для desktop/агентов сохранён |
| 6 | 2FA (TOTP) для admin; passkeys/WebAuthn как следующий шаг | ✅ TOTP RFC 6238 без зависимостей (`users/totp.ts`), `users.totp_secret`; логин → `{ requires2fa, ticket }` → `POST /api/session/2fa`; диалог «Двухфакторная защита» (otpauth-ссылка + ключ) для любого пользователя; passkeys — следующий шаг (⏸) |
| 7 | Журнал безопасности: вход/выход/смена пароля/неудачи с IP и UA, страница в админке | ✅ таблица `security_events` (login/login_failed/login_locked/login_2fa_failed/logout/logout_all/password_set/twofactor_*/user_blocked/unblocked), `GET /api/admin/security?user=&limit=`, вкладка «Безопасность» у пользователя в админке |

## Регистрация и онбординг
| № | Пункт | Статус |
|---|---|---|
| 8 | Саморегистрация по инвайт-ссылке (роль, срок, лимит использований) | ✅ таблица `invites`, админ-роуты create/list/delete (+раздел «Инвайт-ссылки» в админке), публичные `GET /api/session/invite/:token` и `POST /api/session/register` (политика пароля, лимит 5/ч на IP), экран `#/invite/<token>` |
| 9 | Приглашение по email с ссылкой на установку пароля (⏸ SMTP) | ⏸ нет SMTP в окружении; готовая замена — инвайт-ссылка (п.8), которую админ передаёт любым каналом; при появлении SMTP — отправлять ту же ссылку письмом |
| 10 | Сброс пароля: одноразовый код от админа / email (⏸ SMTP для email-варианта) | ✅ «Код сброса» у пользователя в админке (8 символов, 24 ч, хеш в БД), экран входа «Есть код сброса?» → `POST /api/session/reset` (политика, лимит, отзыв сессий) → сессия; email-вариант ⏸ |
| 11 | Обязательная смена временного пароля при первом входе (`mustChangePassword`) | ✅ флажок «временный пароль» при создании, `SessionUser.mustChangePassword`, сервер отвечает 403 `password_change_required` на мутации, клиент показывает обязательный диалог смены |
| 12 | Профиль: смена своего пароля, отображаемое имя, аватар, язык | ✅ «Сменить пароль» в меню аккаунта (`POST /api/session/password`, отзыв остальных сессий); имя и язык ответов были в персонализации; добавлен аватар (эмодзи/буквы) — показывается в кнопке аккаунта |
| 13 | OAuth (GitHub/Google) с привязкой к аккаунту (⏸ client id/secret) | ⏸ нет OAuth-клиентов (client id/secret, redirect URI на прод-домене); точка входа — `users/auth.ts` (`issueSession` выдаёт сессию любому подтверждённому пользователю), таблица привязок `oauth_accounts(provider, subject, user_name)` добавляется при появлении ключей |

## UX и мелочи
| № | Пункт | Статус |
|---|---|---|
| 14 | Экран логина: показать пароль, автофокус, Caps Lock, единая ошибка без раскрытия существования логина | ✅ кнопка 👁 «Показать пароль», подсказка «Включён Caps Lock» (getModifierState), автофокус был; клиент показывает единую «Неверный логин или пароль» (сервер тоже не различает) |
| 15 | «Запомнить меня» — разные TTL сессии | ✅ галка на экране входа → `remember` в login; без неё TTL 12 ч и сессионные cookie (без Max-Age), с ней 30 дней; продление сессии сохраняет её собственный TTL |
| 16 | Уведомление о входе с нового устройства (в чат / email) | ✅ событие `login_new_device` (нет живой сессии с тем же UA+IP), `GET /api/session/me` отдаёт непросмотренные `notices`, клиент показывает тост и шлёт `POST /api/session/notices/seen`; на подтверждённый email уходит письмо с временем/IP/UA и ссылками на смену пароля и отзыв сессий, не чаще раза в сутки для пары IP+UA; выключается в настройках безопасности |
| 17 | Роль `viewer` без права запускать ходы; лимит LLM-расхода на пользователя | ✅ роль `observer` не запускает ходы (`turns.start` → claude.error); `users.llm_limit_usd`: месячный лимит по `usageSummary`, `PATCH /api/admin/users/:name { llmLimitUsd }`, поле «Лимит LLM в месяц» и «Последний вход» в карточке пользователя |
| 18 | Автоотключение неактивных аккаунтов, чистка истёкших инвайтов | ✅ суточный `accountsSweep` в server.ts: `pruneSessions`, `pruneInvites`, `blockInactiveUsers(VC_INACTIVE_DAYS=180; 0 — выкл)` → blocked c причиной `inactive` + событие |
