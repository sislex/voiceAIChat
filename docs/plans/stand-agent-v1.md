Владелец, 2026-10-09: стенд на M2 (MacBook) не создаётся — завести задачу и исправить.

| B01 | Agent | — | Dev stand creation fails on the M2 MacBook with agent 0.24.0 (`apps/agent/src/devProcess.ts`); Kanban 0.2.14 creates a stand by `devProcess.start` with `standId: "<stand>-gateway"`, `component: "core"`, `command: ["npm","run","dev:gateway"]`, `port` 23000 and env `SISLEXA_STAND_MANIFEST`/`SISLEXA_BASE_STAND_URL`/`SISLEXA_GATEWAY_PORT`. Both attempts ended with `process_start_failed` and no diagnostic anywhere. Observed on the machine: (1) attempt 1 (`dev-6dbff81f-797`) cloned the Core mirror, checked out worktree `9160bfbb…`, ran `npm ci`, then failed; its entry stayed in `~/.voicechat/dev-processes/registry.json` and its worktree was not removed; (2) at attempt 2 (`dev-4f4ab9c3-f4d`, same port 23000) a gateway from the OLD worktree `9160bfbb…` was already running (recovered from the stale registry entry), the new start created worktree `11dc209e…`, ran `npm ci`, failed with `process_start_failed`, and both gateway processes were then stopped. Fix: (a) a failed start (any error after the registry write: dependency, spawn, readiness) must remove its registry entry and worktree and never be recovered later; recovery must skip entries that never reached `ready`; (b) `launch`/`launchGateway` must surface the real spawn failure: listen for the child `error` event before checking `pid`, include its code/message (redacted) in the `DevProcessError` message, and log every `devProcess` start/stop/failure with stand, component, sha, port and reason to the agent log; (c) before starting, if the requested port is held by a process this manager owns for another stand that is not in the current request (stale), stop it and clean it up; if held by a foreign process, fail with `port_unavailable` naming the port; (d) keep stand-fixes-v1 B02 behaviour (old process stays until the new one is ready). Tests with fake spawn/readiness: failed start leaves no registry entry/worktree and is not recovered; spawn `error` (e.g. ENOENT/EMFILE) reaches the RPC error message; stale own process on the port is cleaned before a new stand starts; the Kanban gateway request shape above starts and becomes ready. Update `docs/kb` (dev processes topic). Gate: `npm run gate:task -- --base <sha>`. |
