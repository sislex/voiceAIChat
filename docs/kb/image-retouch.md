# Локальная AI-ретушь изображений

## Пользовательский поток

Действие «Локальная AI-ретушь» у сохранённой картинки открывает
`ImageRetouchEditor` из `MessageImage`. Редактор оставляет preview неизменным и
рисует служебную красную область на отдельном canvas. Доступны прямоугольник,
свободное лассо, очистка и повторное рисование; промпт обязателен, изображения-
референсы необязательны и загружаются штатным `uploads:add`.

Координаты pointer переводятся из размера DOM в `naturalWidth/naturalHeight`,
поэтому rectangle и точки lasso сохраняются в системе координат оригинала.
Контракт и чистая геометрия находятся в
`packages/shared/src/imageRetouch.ts`. В web запрос идёт через REST-мост, а
desktop использует тот же `images:retouch` из `IpcInvokeMap`.

## Доверенная граница и обработка

`POST /api/images/retouch` принимает только источник и референсы, уже
принадлежащие текущему разговору либо зарегистрированные в `UploadStore`.
Вложения без `agentId` читаются из runner/server storage с ограниченными
корнями, а удалённые — через файловый API указанной доступной машины.

`apps/server/src/imageRetouch.ts` декодирует оригинал через Sharp, валидирует
геометрию и извлекает минимальный bounding crop. Генератор получает только этот
crop, локальную чёрно-белую маску, промпт и референсы; весь исходный кадр модели
не передаётся. Адаптер `llm/imageRetouchGenerator.ts` запускает Codex без
исполнения команд и принимает первый штатный image-блок результата.

Ответ модели должен быть поддерживаемым растром точного размера crop. Перед
сборкой проверяется перепад на внутренней границе маски. Сервер копирует raw RGBA
ответа только в белые пиксели маски, а затем побайтно подтверждает идентичность
всех пикселей вне полной маски исходному декодированному изображению. Служебная
визуализация canvas в обработку не попадает; растушёвывание за границу маски
невозможно. Ошибка генерации, формата, размера, стыка или outside-проверки даёт
`422` и не создаёт сообщение.

## Результат и история

Успешная сборка кодируется отдельным PNG. Для удалённого оригинала
`saveRetouchedImage` пишет его в `.generated_images` корня машины-источника
через `AgentRegistry`; локальный результат сохраняется в том же каталоге
профиля пользователя на сервере. Затем сервер атомарно добавляет AI-сообщение со
штатным image-блоком и вложением с правильным `agentId`.

`MessageAttachment.retouch` хранит источник, выделение, промпт и необязательные
референсы. Эти данные входят в обычную историю сообщений без отдельной таблицы;
при повторном открытии результата UI берёт исходник и восстанавливает выделение.
