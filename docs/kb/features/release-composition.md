# Состав релиза из опубликованных выпусков приложений

Релиз Core можно собрать из выбранных на странице релизов версий приложений (Make, Web Reader,
Playwright Reader, llm-runner, core-ui, Desktop и других владельцев). Выбранные выпуски
закрепляются в ветке `release/X` тем же способом, каким раньше закрепляли их вручную PR-ом, и
регрессия узнаёт чистую замену закреплений (`scripts/owner-pins.mjs`) — идёт суженный план.

## Опубликованный выпуск

Выпуск приложения — GitHub-релиз `vX.Y.Z` в репозитории владельца. В нём:

- npm-архивы, которые Core закрепляет в `vendor/`, с именем `<пакет>-<версия>-<sha256[:12]>.tgz`;
- манифест `sislexa-release.json` (`packages/shared/src/releaseComposition.ts`):
  репозиторий, версия, **коммит**, пакеты с `sha256`/`integrity`/размером, образы в GHCR
  (тег образа — коммит) и ключи `deploy/tools.lock.json`, которые берут версию и коммит выпуска.

Сервис без npm-архивов (Kanban) выпускается одним образом: `packages` пустой, есть образ и
инструмент `kanban` в `deploy/tools.lock.json`. Пустой выпуск — без пакетов и образов — отклоняется.

Идентичность выпуска — коммит: номер 1.3.1 у Make однажды публиковался дважды с разными байтами.
Поэтому публикация отказывается выпустить уже занятую версию из другого коммита.

## Публикация

`scripts/owner-release-publish.mjs`, токен `GITHUB_TOKEN` с правом создавать релизы:

- `--source <чекаут владельца>` — чистый чекаут на коммите выпуска: `npm run pack:release`,
  образы из `OWNER_IMAGES` (`docker build --target … -t ghcr.io/sislex/<имя>:<коммит>` и `push`),
  затем GitHub-релиз с архивами и манифестом. `--skip-images`, если образы уже опубликованы;
  `--dry-run` печатает манифест, ничего не публикуя.
- репозиторий без `pack:release` (Kanban) публикует только образ: гейт владельца идёт внутри
  `docker build`, архивов нет.
- `--from-core <repository>` — один раз опубликовать то, что уже закреплено в Core, из `vendor/`:
  это ровно те байты, что стоят на проде. Если пакеты репозитория закреплены на разных коммитах,
  выпуск берёт коммит инструмента (`tools.lock`), остальные пакеты в него не входят. Образ входит,
  только если compose закрепил его на том же коммите.

## Закрепление

`node --import tsx scripts/release-composition.mjs apply --dir <каталог>` — по подкаталогу на
выпуск с манифестом и архивами. Сначала всё проверяется (байты и хэши, имя, версия и коммит внутри
архива, пакет уже закреплён и из того же репозитория, инструмент и образ есть в Core), потом
переписываются `vendor/*.tgz`, `vendor/owner-artifacts.json`, `vendor/ui-libraries.json`,
`dependency-snapshots.json`, `package.json` всех пакетов, `package-lock.json`,
`deploy/tools.lock.json` и образы в compose. Новый пакет составом релиза не добавляется — это
изменение Core отдельным PR. `current` печатает закреплённые выпуски по репозиториям.

Проверено на истории: закрепление Make 1.3.0 поверх Make 1.3.1 дало те же строки манифестов и
`tools.lock`, что ручной PR #272, а планировщик регрессии — `onlyPins`.

## Выпуски, замороженные приёмкой shared-chat-v1

identity 1.4.2, billing 1.2.2 и llm-runner 0.3.5 (с `runner-contracts`) не выбираются на вкладке:
их архивы закреплены приёмкой A07/S3 (`scripts/a07-composition.mjs#requiredSources`,
`deploy/s3-provider-artifacts.json`) на коммитах, которые не совпадают с тегами версий
владельцев, поэтому опубликовать их выпуском нельзя — тег `vX.Y.Z` уже стоит на другом коммите,
а публикация на чужой тег запрещена:

| Владелец | Архив в Core | Тег версии | Расхождение |
| --- | --- | --- | --- |
| identity | `e33958b` | `v1.4.2` → `c7aaebd` | архив новее тега, версия не повышена |
| billing | `41263c7` | `v1.2.2` → `bf811d6` | архив новее тега, версия не повышена |
| llm-runner | `1ccbdeb` | `v0.3.5` → `ad0819a` | коммит архива не лежит ни в одной ветке; образ в compose — 0.3.6 (`849f139`) |

Сделать их выбираемыми можно только вместе с новой приёмкой: владелец выпускает следующую версию
(`owner-release-publish.mjs --source`), Core закрепляет её, а `requiredSources` и S3-манифест
обновляются с новыми свидетельствами A07. Ослаблять проверку A07 ради выбора версии нельзя.
