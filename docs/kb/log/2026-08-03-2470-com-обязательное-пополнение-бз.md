# обязательное-пополнение-бз

## Что сделано

- Правило «пробел базы знаний обязан стать записью» вынесено в директивы модели:
  `KB_GAP_RULE` в новом `packages/shared/src/kbGaps.ts` уходит в `kbToolHint`
  (системный хинт КАЖДОГО хода с инструментами БЗ — чат, работа модели рана,
  fix-loop, резюме) и в `kbRunDirective` вместе с форматом блока ` ```kb-gaps `.
- В ране пробелы копятся: `parseKbGaps` снимает блок с каждого хода работы модели
  и с каждой попытки fix-loop, `db.addCiRunKbGaps` пишет их в новую таблицу
  `ci_run_kb_gaps` (ключ «ран + вопрос», повтор берёт более полный ответ).
- Шаг «Актуализировать базу знаний» получил их в промпт (`gapsBlock` в
  `kb/codeUpdate.ts`) плюс объективную половину — `db.kbUsageRunGaps`: обращения
  со статусом `empty`/`error` из телеметрии. Пустой диф с пробелами ход модели
  теперь делает; пустой диф без пробелов, как раньше, закрывается «нечего
  обновлять».

## Что выяснили (факты, которых не было в KB)

- `kbToolHint` добавляется исполнителем только при наличии `kbMcpUrl`
  (`claudeCli.ts`, `codexCli.ts`) — это единственное место, которое видят все
  фазы рана сразу, поэтому общее правило живёт там, а не в промпте каждой фазы.
- Ход шага `kb_update` инструментов БЗ не получает вовсе (он пишет, а не читает),
  поэтому требования к записи должны быть в его собственном промпте.
- Статус `empty` в `kb_usage_queries` уже хранит человеческую причину в `error` —
  готовый источник «база не ответила» без новых полей.

## Открытые вопросы / что осталось

- Пробелы рана нигде не показаны в UI (ни в ленте рана, ни в модалке задачи):
  видно только строку «Пробелов базы знаний за ран: N» в логе шага.
- Признак «ответ базы был неполным» остаётся словом модели: телеметрия отличает
  только «ответа не было». Объективный сигнал (обрезка раздела капом) не пишется.
