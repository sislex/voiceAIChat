# task-timeline

## Что сделано

- Сверена серверная агрегация временной шкалы и дополнено описание стабильной истории попыток и порядка этапов.

## Что выяснили (факты, которых не было в KB)

- Исходные раны сохраняются отдельными попытками; группировка по типу этапа не перезаписывает повторные и параллельные запуски.
- Этапы сортируются по позиции workflow, затем по фактическому времени и стабильному id.
