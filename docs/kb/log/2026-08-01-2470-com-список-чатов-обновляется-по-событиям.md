# Список чатов обновляется по событиям, а не только по действиям

## Что сделано

- `voiceStore.ts`: общий `scheduleConversationsRefresh()` — перезапрос списка
  бесед со склейкой в окно `CONVERSATIONS_REFRESH_DEBOUNCE_MS` (300 мс). Таймер
  гасится в `dispose()`.
- Поводы дёрнуть список: `applyCiDone`, `applyCiSummary` с терминальным статусом
  (`isTerminalCiStatus`), `applyChatMessage` для неактивного чата (раньше метод
  молча выходил) и `applyBoardUpdate`, когда изменился набор задач в колонках с
  семантикой `done` (`doneTaskIds`/`sameDoneTasks`).
- `refreshConversations({ keepActiveListed })` + `pinActiveIfHidden`: при фоновом
  обновлении активный чат, пропавший из ответа сервера, закрепляется
  (`pinnedConversation` → `keepPinned`). Тем же флагом ходит `moveTask`.
- Тесты: `packages/ui/src/store/voiceStore.sidebar.test.ts` (уход строки по
  `ci.done`/`ci.summary`, закреплённый открытый чат, `chat.message` в фоновый чат,
  возврат карточки через `board.update`, отсутствие шторма на `ci.log`/`ci.step`).

## Что выяснили (факты, которых не было в KB)

- Ни один обработчик кадров `ci.*` список бесед не трогал: его обновляли только
  действия пользователя и `bootstrap()`. Поэтому чат последней завершённой задачи
  висел в сайдбаре до перезагрузки — предыдущие уходили лишь потому, что список
  случайно перезапрашивался по другому поводу.
- `keepPinned` спасал только чат, который **открыли уже скрытым**
  (`pinnedConversation` ставится в `selectConversation`, если строки нет в
  списке). Когда задача завершается при уже открытом чате, закреплять было
  нечего — понадобился `pinActiveIfHidden` на фоновом обновлении.
- Закреплять активный чат на любом `refreshConversations` нельзя: удаление
  активного чата тоже убирает его из ответа сервера, и строка удалённого чата
  вернулась бы в список. Отсюда флаг `keepActiveListed` только для фоновых
  обновлений.

## Куда занесено

- `docs/kb/ui.md` — новый раздел «Список бесед обновляется по событиям».
- `docs/kb/projects.md` — «Чаты завершённых задач скрыты из списка бесед»:
  клиент сам сходится с сервером, ссылка на раздел в ui.md.

## Открытые вопросы / что осталось

- `board.update` обрабатывается только для открытой доски (`activeProjectId`).
  Ручной перенос карточки другим участником при закрытой доске сайдбар не
  обновит — до ближайшего события CI или действия пользователя.
