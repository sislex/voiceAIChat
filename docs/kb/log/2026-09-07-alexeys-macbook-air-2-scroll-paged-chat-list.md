# scroll-paged-chat-list

Продолжение `lazy-chats-and-pagination`: модель загрузки списка бесед сменилась по
просьбе пользователя — вместо окна недели с кнопкой «Более старые» теперь
последние 20 и автоподгрузка при прокрутке.

## Что сделано

- Первая страница — последние `CONVERSATIONS_PAGE` (20) бесед: `conversations:list`
  с `limit`, без `since`. Дальше прокрутка списка до конца просит следующую
  (`loadMoreConversations`, `moreStatus`, `hasMoreConversations`).
- Секции «На этой неделе» / «Более старые» остались **разделителями**: не
  сворачиваются, кнопки и счётчика у них больше нет.
- Обновление списка перечитывает ровно столько, сколько уже показано.

## Что выяснили (факты, которых не было в KB)

- **Курсор пагинации нельзя считать по видимому списку.** Первая реализация брала
  самую старую из `state.conversations`; страница, целиком отсеянная фильтром
  проектов сайдбара, не меняла список — и тот же запрос уходил по кругу, вешая
  вкладку (CDP `Runtime.evaluate` отваливался по таймауту, рендерер не отвечал).
  Курсор двигается по последней **полученной** беседе и живёт вне состояния.
- Одной прокрутки мало: двадцать бесед помещаются на широком экране целиком
  (`scrollHeight <= clientHeight`), и события `scroll` не будет вовсе. Нужен
  отдельный эффект «список короче контейнера — грузим сразу».
- Проверено на копии боевой базы: 20 бесед на старте, прокрутка даёт 40 → 60 → 79.

## Куда занесено

- docs/kb/ui.md — страницы по 20, правило курсора, короткий список.
- docs/kb/protocol.md — `limit` как основной параметр списка.

## Открытые вопросы / что осталось

- `since` остался в контракте `conversations:list`, но клиентом больше не
  используется: пригодится, если вернётся недельное окно.
