# b02-ticket-delegation

## Что сделано

- Погашение тикета (`/internal/v1/tickets/redeem`) теперь возвращает делегирование ядра `delegation: { token, expiresAt }`: токен `sxd_…`, в памяти хранится только хэш, срок совпадает со сроком сессии (8 ч).
- Ядро принимает этот токен в `x-sislexa-delegation` только вместе с учётными данными сервиса того же приложения; права — чтение, запись и запуск в собственных беседах пользователя.
- Ход через такое делегирование идёт по сессии пользователя, выдавшей тикет, с атрибуцией биллинга приложению. `CoreDelegationClient` по умолчанию берёт токен из сессии.

## Что выяснили (факты, которых не было в KB)

- Контракт B01 не давал сервису полномочий на ходы в ядре: задача C03 (Make) остановилась на этом пробеле.
- Раньше `expiresAt` в ответе погашения был сроком самого тикета (60 с), поэтому сессия сервиса истекала через минуту.

## Куда занесено

- docs/kb/data-auth.md — раздел «Core-issued ticket delegation».
- docs/kb/architecture.md — `CoreDelegationClient` и `redeem()`.

## Открытые вопросы / что осталось

- Делегирования живут в памяти процесса: после перезапуска ядра сервис должен заново войти через тикет.
