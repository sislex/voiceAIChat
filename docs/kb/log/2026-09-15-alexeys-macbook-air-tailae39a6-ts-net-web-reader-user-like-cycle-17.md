# web-reader-user-like-cycle-17

## Что сделано

- Цикл 17 серии «Web Reader: браузер как у пользователя». Модель: `search` по полю поиска самого сайта,
  `focus`, `select`, `read {main}`, `read.breadcrumbs`, `read.pagination`, `read.published`, `read.search`,
  `wait {stable}`, `back {to}` по истории сеанса панели.
- Панель: путь по сайту с переходами, ряд листалки и Alt+Shift+стрелки, «Искать на сайте» и клавиша «/»,
  дата и автор рядом с названием, подпись «Ассистент выделил», восстановление места чтения при возврате,
  обновлённая шпаргалка клавиш, горизонтальная прокрутка ориентиров с 44 px на тач-экранах.
- Гейт модуля зелёный по коду возврата: typecheck и тесты shared, web-reader, web-reader-app, web-recorder,
  web-reader-contracts, ui.

## Что выяснили (факты, которых не было в KB)

- Панели нужны данные страницы, которых нет в контракте host-а. Их можно возить внутренним каналом
  рекордер ↔ инъецированный скрипт (`page-ready.nav`), не трогая версионированный `@shared/webRecorder`:
  контракт с ChatAI остаётся прежним, а UI получает крошки, листалку и дату.
- Собственные действия панели к своей странице (поиск по сайту, установка курсора) отправляются с
  requestId-префиксом `ui-`: host о них не знает, как и о нажатиях человека, — это не ход модели.
- Каждый переход пересоздаёт iframe (`frameKey`), поэтому восстановление места чтения и любые проверки
  окна страницы в тестах нужно делать на окне уже новой страницы, а не на сохранённой ссылке.
