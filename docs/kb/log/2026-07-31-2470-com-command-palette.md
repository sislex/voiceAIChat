# command-palette

## Что сделано

- `packages/ui/src/lib/commands.ts` — реестр команд без React (замыкание, как
  стор): `registerCommand`/`registerCommandSource`/`listCommands`/
  `subscribeCommands`, «недавние» в `localStorage` и `searchCommands` (группировка
  по разделам, сортировка по весу, ограничение выдачи со счётчиком скрытых).
  React-подключение — `lib/useCommands.ts` (`useCommandSource`, `useCommandRegistry`).
- `lib/fuzzy.ts` — нечёткий поиск: подпоследовательность, вес за начало слова и за
  совпадение подряд, индексы совпавших букв для подсветки.
- `lib/hotkeys.ts` — разбор комбинаций (`mod+k`, `Space`, `?`), сверка с событием и
  подпись (`⌘K` / `Ctrl+K`). `lib/useHotkeys.ts` переписан на карту биндингов
  `HotkeyBinding[]`; пробел и Esc остались первыми биндингами с прежним поведением.
- `lib/appCommands.ts` — базовый набор команд и пункты по данным (беседы, проекты,
  задачи открытой доски, машины) плюс `buildHotkeyBindings` для ⌘K и «?».
  `App.tsx` только передаёт состояние и колбэки.
- `components/CommandPalette.tsx` — палитра поверх общего `Dialog`: поиск с
  подсветкой, разделы, «Недавние», ↑/↓/Home/End/Enter, мышь наравне.
  `components/HotkeysCheatSheet.tsx` — шпаргалка по «?», генерируется из реестра.
- Экраны регистрируют свои команды: `KanbanBoard` — «Создать задачу»,
  `RunFeed` — «Повторить последний ран». `Sidebar` получил кнопку «⌘K» у поиска.
- Стили: блоки `.cmdk-*` и `.hkeys-*` в `app.css`, целиком на токенах.
- Тесты: `fuzzy` (10), `hotkeys` (11), `commands` (18), `appCommands` (22),
  `useHotkeys` (15, из них 7 новых про карту биндингов), `CommandPalette.dom` (16),
  `HotkeysCheatSheet.dom` (8), `App.commands.dom` (8), плюс проверки реестра в
  `KanbanBoard.dom` и `RunFeed.dom`. Сториз — `CommandPalette` (8, включая
  `HugeList` на 600 бесед) и `HotkeysCheatSheet` (3).

## Что выяснили (факты, которых не было в KB)

- **Жадный fuzzy даёт кривую подсветку.** Проход «первое совпадение слева»
  подсвечивает «кп» в «Командная палитра» как «Ко…мандная»: вторая буква находится
  внутри первого слова раньше, чем в начале второго. Нужен DP по таблице n×m
  (подход fzy) с весами «начало слова» / «подряд» — строки короткие, это дешевле,
  чем объяснять пользователю прыгающую подсветку.
- **Источник команд обязан быть функцией.** Готовый массив устаревает в момент
  регистрации (колбэки замыкают пропсы), а перерегистрация на каждый рендер
  пересобирала бы открытую палитру на каждое нажатие клавиши. Решение: функция в
  ref, регистрация один раз за жизнь экрана, список собирается при открытии окна.
- **Дубли команд реальны.** `RunFeed` бывает на странице дважды (модалка ленты и
  шапка связанного чата), поэтому реестр склеивает по `id` — иначе «Повторить
  последний ран» дублируется в выдаче.
- **Пробел и Esc до карты биндингов ловились без проверки модификаторов** (только
  `e.code`). Общая сверка комбинации это ломает: Ctrl+пробел перестал бы начинать
  запись. Поэтому у них флаг `ignoreModifiers`.
- **Высоту палитры надо фиксировать на окне, а не на списке.** `min-height` списка
  не спасает: окно центрировано по оверлею, и на каждую букву оно прыгало по
  вертикали (проверено в браузере: 521 → 501 → 446px). Фиксированная высота
  `.cmdk` + `flex: 1` у списка держит окно на месте (560px на десктопе, полный
  экран на телефоне).
- **`.vc-btn` не имеет `min-height`.** Кнопка «⌘K» рядом с поиском получалась
  вдвое ниже поля; лечится `align-items: stretch` у ряда, а не подбором padding.
- **Шпаргалка не должна фильтровать по `enabled()`.** Иначе «удерживайте пробел»
  пропадает ровно во время записи — тогда, когда подсказка и нужна.
- **Конфликта ⌘K в Electron нет**: `apps/desktop` не вызывает
  `Menu.setApplicationMenu` и не регистрирует `globalShortcut` (только меню трея),
  а в дефолтном меню Electron ⌘K не занят.

## Открытые вопросы / что осталось

- Задачи в палитре — только из **открытой** доски: снапшота задач всех проектов в
  памяти нет, а серверного поиска по задачам под это не делали. Поиск «#42» без
  открытого проекта ничего не найдёт.
- `typecheck:desktop` в этом клоне не запускается: зависимости `apps/desktop`
  (electron, electron-vite) не установлены. Проверено чтением кода.
- Реальная запись голоса не проверялась поведенчески: `VOICE_INPUT_ENABLED = false`,
  и `voice` в тестах не доходит до `listening`. Правило «⌘K во время записи
  игнорируется» покрыто юнит-тестом `buildHotkeyBindings`.
