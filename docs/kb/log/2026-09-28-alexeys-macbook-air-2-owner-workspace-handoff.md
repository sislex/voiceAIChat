# owner-workspace-handoff

## Что сделано

- Добавлен канонический путь owner-workspace вне основного checkout задачи: `<storage>/projects/<projectId>/tasks/<taskId>/owners/<ownerId>/repository`.
- CI-runner перед синхронизацией, моделью и push проверяет рабочее дерево на вложенные Git-репозитории и останавливается с кодом 66 вместо продолжения с неоднозначным checkout.
- В окружение рана добавлен `OWNER_WORKSPACES_ROOT`; диагностика сообщает путь, origin, ветку, HEAD, dirty-состояние и наличие опубликованного remote SHA.
- Добавлены unit-тесты shared path helper и серверного guard; пройдены typecheck и целевые тесты shared/server.

## Что выяснили (факты, которых не было в KB)

- Вложенный полноценный checkout отображается для внешнего репозитория как untracked-каталог и способен скрывать локальный коммит, поэтому автоматическое удаление, перемещение или stash небезопасны.
- Безопасная граница переноса разработки между машинами — опубликованный Git SHA; локальный неопубликованный коммит остаётся только на исходной машине.
- Gitlink/submodule с режимом `160000` является допустимым вложенным Git-контролем и не должен блокироваться guard-проверкой.

## Открытые вопросы / что осталось

- Автоматическая передача эксклюзивной lease между машинами и отдельный UI handoff в эту итерацию не входят; текущая реализация создаёт безопасную файловую схему и предотвращает повтор исходной аварии.
