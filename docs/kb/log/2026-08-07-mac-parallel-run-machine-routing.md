# parallel-run-machine-routing

## Что сделано

- CHAT-134: параллельный запуск CI-рана мимо очереди (`launch: 'parallel'`),
  автоподбор машины по загрузке (`pickCiRunAgent` + `countActiveCiRunsByAgent`),
  принудительный запуск на явной машине из настроек задачи
  (`POST …/ci/run-on-machine`, `forceStartOnMachine`) с продвижением
  ожидающего рана из очереди без отмены (`promoteQueuedRun`).
- `execute` теперь берёт машину из записи рана (`runRow.agentId`), а не из
  `project.defaultAgentId` — выбор машины наконец доезжает до исполнителя.

## Что выяснили (факты, которых не было в KB)

- До правки `execute` игнорировал `ci_runs.agent_id` и всегда работал на машине
  проекта по умолчанию, хотя запись рана и валидация в `start` машину фиксировали.
