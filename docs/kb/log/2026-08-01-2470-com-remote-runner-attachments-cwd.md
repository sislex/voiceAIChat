# Вложения и cwd теперь разрешаются на стороне исполнителя

## Что сделано

- Дополнена KB по удалённому исполнителю: вложения больше не зависят от абсолютных путей сервера, а `cwd` больше не валидируется в `turns.ts` до отправки запроса.

## Что выяснили (факты, которых не было в KB)

- Сервер передаёт в `LlmRequest.attachments` не только имя файла, но и `serverPath` с `dataBase64`, потому что prompt уже собран с серверными путями.
- `RunManager.prepareRun()` создаёт временный каталог `voicechat-llm-run-*`, раскладывает туда вложения, переписывает prompt по карте `serverPath -> runnerPath` и удаляет каталог при завершении, отмене, обрыве клиента и ошибке `spawn`.
- `LlmRequest.cwd` стал желаемым каталогом: проверка существования перенесена на хост исполнителя, а несуществующий путь просто не попадает в `spawn`.

## Открытые вопросы / что осталось

- Реестр исполнителей всё ещё берётся из env; перенос файловых API и выбора исполнителя в полноценный registry остаётся отдельной задачей.
