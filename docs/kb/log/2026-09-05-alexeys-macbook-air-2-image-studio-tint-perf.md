# image-studio-tint-perf

## Что сделано

Итерация 65 студии картинок: разобрана причина, по которой порядок «По цвету»
занимал вкладку на десятки секунд. Три правки — байты из готового превью,
счётчик прогресса по партиям, пометка кадров без цвета. Проверено живьём на
88 файлах: порядок применяется, вкладка отвечает мгновенно.

## Что выяснили (факты, которых не было в KB)

- **`blobOf` читал файл через мост, хотя тот же файл уже лежал blob-URL'ом**
  в превью. Плюс декодирование `Uint8Array.from(atob(s), (c) => c.charCodeAt(0))`
  — колбэк на каждый байт, синхронно в главном потоке. Теперь: сперва
  `fetch(previewUrl)`, запасной путь — цикл вместо колбэка.
- **Состояние-индикатор в тяжёлой сетке нельзя обновлять по одному кадру**:
  каждое обновление перерисовывает всю галерею. По партиям (раз в 24 кадра)
  разница между «вкладка не отвечает» и «мгновенно».
- **Кадр может обработаться без исключения и всё равно не дать цвета**
  (прозрачный PNG, канвас без 2d-контекста, заглушка `createImageBitmap` в
  тестах). Если помечать только исключения, партия из таких кадров крутится
  в очереди вечно — тест это и поймал.
- Замер на dev-стенде: одно чтение файла через мост — 65 мс, `createImageBitmap`
  — 3 мс. То есть узкое место — именно чтение и декодирование, а не картинка.
