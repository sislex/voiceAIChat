# web-reader-self-preview-hash-and-cache

## Что сделано

- Диагностирована жалоба «Web Reader не открывает свой же ChatAI (#/machines)».
  Живая проверка показала: транспорт работал, но (а) вложенный ChatAI показывает
  свой экран «Вход» (изолированный шимованный localStorage — токен верхней сессии
  внутрь не протекает, это норма), (б) hash `#/machines` терялся — вложенный SPA
  открывался на дефолтном маршруте.
- Context-шим `/api/preview` теперь восстанавливает фрагмент целевого адреса:
  `location.hash = target.hash`, если у документа hash пуст (`previewProxy.hash.test.ts`).
- Починен залипающий кэш переписанного HTML: браузерные conditional-заголовки
  (`if-none-match` и родня) больше не уходят апстриму, а `etag`/`last-modified`
  апстрима вырезаются из ответа (`DROPPED_RESPONSE_HEADERS`); тест в
  `previewProxy.machine.test.ts`.
- Живая проверка: `…machine.internal:5273/#/machines` → вход admin → страница
  «Машины» с живой телеметрией внутри Reader. Гейт сервера зелёный (1255 тестов).

## Что выяснили (факты, которых не было в KB)

- 304 от апстрима на проброшенный `if-none-match` заставлял браузер брать из кэша
  старый инъецированный HTML: валидаторы описывают апстримное тело, а прокси его
  переписывает. Vite-окружения с `etag` на `index.html` воспроизводили это стабильно —
  обновления шимов «не доезжали» до открытых превью.
- Self-preview ChatAI работоспособен целиком после входа: WS вложенный клиент
  открывает мимо шима на реальный origin (тот же сервер), токен вложенной сессии валиден.

- docs/kb/machines.md — абзац про ChatAI внутри собственного Web Reader.

## Открытые вопросы / что осталось

- WS произвольных чужих окружений через `/api/preview` по-прежнему не проксируется
  (self-ChatAI — счастливый случай same-origin).
