# gallery-file-cache-and-noindex

## Что сделано

Итерация 69 студии картинок (7 пунктов): у публичной ручки файла появились
ETag и 304 вместо `no-store`, картинки помечены `noindex, noimageindex`.
Тест на весь цикл (200 → 304 → новый ETag после подмены), проверки живьём
curl'ом, обход пути перепроверен.

## Что выяснили (факты, которых не было в KB)

- **`no-store` на картинках публичной галереи** означал полную перекачку при
  каждом заходе: у зрителя на 90 кадров это заметно даже локально. ETag по
  sha1 содержимого + `private, no-cache` дают 304 без тела, но не рискуют
  устаревшей картинкой: файл под тем же именем могли заменить.
- **`x-robots-tag` стоял только на HTML-странице**, а на самих файлах — нет.
  Прямая ссылка на кадр — обычный URL, и одной публикации где-нибудь хватит,
  чтобы картинка попала в поиск по картинкам мимо приватности токена.
- Проверки без находок: обход пути закрыт на уровне имени
  (`?path=../../../package.json` → 400 «Недопустимое имя файла»), несуществующий
  токен даёт 404, страница отдаётся с `no-store` (правильно: список меняется).
- Тонкость проверок curl'ом: кириллические имена нужно кодировать самому,
  иначе сервер отвечает 400 на существующий файл и это выглядит как дефект.

## Куда занесено

- docs/kb/ui.md — раздел «Студия картинок», абзац «Итерация 69»
- docs/kb/protocol.md — заголовки ответа `/g/<token>/file`

- **Флейк в `apps/server/src/session.test.ts`**: тест «claude.cancel с
  conversationId снимает ход: partial сохраняется как interrupted и поздний
  done игнорируется» в полном прогоне гейта один раз упал (в `meta` вместо
  `interrupted: true` приехали `durationMs`/`model`/`request` — то есть поздний
  `done` всё-таки записался), а изолированно и на повторном полном прогоне
  прошёл. Гонка отмены и позднего `done`; к студии отношения не имеет.

## Открытые вопросы / что осталось

- Счётчик просмотров считает заходы на страницу; 304-ответы по файлам его не
  трогают — это осознанно, но стоит помнить при разборе статистики.
