# chat-mode-stop-defects

## Что сделано

- Новый маршрут `POST /api/conversations/:id/context-configuration`: режим ассистента и весь список отключённых блоков пишутся одним запросом (`replaceConversationDisabledContext`), последний запрос побеждает.
- `POST /api/conversations/:id/context/:itemId` при активном Required больше не отвечает ошибкой на `enabled: false` — блок и так выключен, возвращается снимок.
- «Стоп» сохраняет остановленный ответ и без текста (раньше — только на стенде с API моделей).
- Текстовый ход (Chat, Required, API моделей) не записывает `permissionMode` в сведения о запросе; раннеру режим по-прежнему передаётся — Codex использует его как песочницу.

## Что выяснили (факты, которых не было в KB)

- Core UI применяет Required серией запросов: по одному `context/:itemId` на блок (каждый отвечает полным снимком, около 0,5 с), маркер — последним. Отсюда 12,6 с на проде и гонка: обратное переключение идёт одновременно с первым, и первое дописывает блоки и маркер после него.
- Ошибка «Источники базового мода Required меняются в редакторе мода» — ответ на поблочный запрос, пришедший после установки маркера.
- Тесты `session.test.ts` группы «форс plan» падают по таймауту 5 с и на чистом dev на этом Mac (один тест идёт 3,7–5 с).

## Куда занесено

## Открытые вопросы / что осталось

- Core UI должен перейти на новый маршрут (`applyContextConfiguration` в `packages/ui/src/modules/shell/App.tsx`); до этого гонка остаётся.
- «Стоп» в фазе подготовки хода (до регистрации хода в `turns`) не проверялся.
