# component-rotation-containers

## Что сделано

- Автоматическое продление токенов компонентов переписано: `scripts/prod/component-rotation.sh` работает от root через запущенные контейнеры (выпуск токена внутри контейнера-поставщика от владельца реестра, перенос файла на хосте с прежними владельцем и правами, перезапуск продлённых потребителей). Добавлены `--dry-run`, `--days`, `--pair`.
- Служба теперь от root, таймер — раз в сутки в 03:30 UTC вместо ежечасного.
- Установлено на проде 2026-11-19, пробный прогон без изменений прошёл, продление одной пары (web-reader → playwright-reader) проверено.

## Что выяснили (факты, которых не было в KB)

- 19.11 истекли все токены, выпущенные 20.10: API моделей отвечал `503 accounting_unavailable`. Прежняя служба падала каждый час: UID 1000 не может войти в `/root`, на хосте нет Node, установка собрана из каталогов и символических ссылок, которые `component-rotation.mjs` отвергает.
- Каталоги `outgoing` смонтированы в контейнеры только для чтения; записывать можно в `/run/sislexa/provider`. `docker exec` по умолчанию идёт от root, а реестр требует владельца файлов.
- В образе tts-runner лежат контракты и tts, и stt — контракт нужно выбирать по `applicationId`.
