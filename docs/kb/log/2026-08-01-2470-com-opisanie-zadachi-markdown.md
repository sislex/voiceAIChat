# Описание задачи: маркдаун в просмотре, правка по кнопке

## Что сделано

- В `TaskModal` описание по умолчанию рендерится через `Markdown` (как ответы в
  ленте чата), правка — по кнопке «Изменить описание» (`task-desc-edit`), поле
  `rows={10}` без `useAutoGrow`, коммит по «Сохранить»/`onBlur`, «Отмена»/Esc —
  без записи. Пустое описание — кликабельная подсказка (`task-desc-empty`).
- CSS секции (`.jmodal-desc-head/-view/-empty/-actions`) + мобильные кегли в
  `packages/ui/src/styles/app.css`; сториз `DescriptionMarkdown` и
  `DescriptionEditing`; DOM-тесты на просмотр/правку/отмену/сброс режима.

## Что выяснили (факты, которых не было в KB)

- Esc внутри поля не поймать своим обработчиком: `useDialogStack` слушает
  `window` в capture и гасит событие. Правка описания отвечает на общий запрос
  закрытия карточки (`Dialog onEscape` → `requestClose`), своего слоя стека не
  заводит: первый Esc возвращает просмотр, второй закрывает карточку.
- `onBlur` пришлось сузить проверкой `relatedTarget` внутри `.jmodal-desc-wrap` —
  иначе уход фокуса на «Отмену» записывал бы черновик раньше её клика.
- Палочка AI (`useAiAssist`) живёт только в правке; тесты, дергавшие её в
  карточке (`KanbanBoard.dom.test.tsx`, `TaskModal.dom.test.tsx`), теперь сперва
  открывают правку.
