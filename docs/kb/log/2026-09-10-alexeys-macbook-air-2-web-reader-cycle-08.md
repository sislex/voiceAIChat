# web-reader-cycle-08

## Что сделано

Десять исправлений интеграции модели перечислены в плане. Один open делает одну
загрузку; cookie выпускается до запроса, сохраняется конечный URL после ready.
Сбой сохранения виден и повторяется без reload. Ответы используют исходный ID
регистрации; устаревшая диагностика игнорируется. Relay сообщает result.page.
61 unit/DOM + 33 relay/MCP, typecheck UI, web build и 11 Chromium — код 0.

## Что выяснили

В исходном App reader.changed(navigated) повторно монтировал Reader — браузерный
baseline после правильной настройки стенда показал две загрузки одного open.
Первый таймаут baseline был ошибкой стенда: алиас читался из process.env, а не
переданного loadConfig. Чтение разговора требует scope=web-reader и conversation
из конверта ответа. Эти ошибки стенда не засчитаны в исправления приложения.
