# lazy-chats-and-pagination

Продолжение разбора медленного старта (см. `board-two-phase`): те же приёмы для
списка бесед и меток чатов задач. Проверено на локальной копии боевой базы.

## Что сделано

- **Канбан не грузит чаты.** `bootstrap` получил `skipConversations`: старт на
  маршруте доски не выполняет шесть `conversations:list` и `task-chats`. Индекс
  просит тот, кто его показывает — `ensureConversationIndex` (один раз за
  сессию): вкладка «Чаты», ссылка на чат, переход в чат задачи с доски.
  `refreshConversations`/`scheduleConversationsRefresh` молчат, пока индекс не
  загружен, — события доски больше не тянут скрытый список.
- **Список бесед пагинируется.** Первая страница — окно текущей недели
  (`conversations:list` с `since`), «Более старые» раскрывается и тянет по 20
  (`before` = пара `updatedAt` + `id`, `limit`), внизу — «Показать ещё 20».
  Обновление списка перечитывает окно и сохраняет уже догруженные старые.
- **`task-chats` без сводок ранов.** Поле `run` стало опциональным и приезжает
  только по `?withRuns=1`.

## Что выяснили (факты, которых не было в KB)

- В ответе `task-chats` (377 меток, 1.2 МБ) на `run` приходилось 1596 КБ, из них
  1397 КБ — `progress` (раскладка шагов с прогнозами). Сайдбар рисует из сводки
  только состояние подсветки, а сама она собиралась пятью запросами на метку.
- Замеры на копии боевой базы:
  `task-chats` 1.2 МБ / 0.42 с → 78 КБ / 2.5 мс;
  список бесед 158 записей, 117 КБ / 0.8–1.0 с → окно недели 22 записи, 15 КБ /
  25 мс, порция старых 14 КБ / 38 мс;
  открытие канбана — ноль запросов по чатам (было два списка и две метки).
- `runtime.start` теперь принимает `BootstrapOptions`; признак «стартуем на
  доске» считает `App.tsx` через `parseProjectsRoute` при монтировании.
- Курсор пагинации обязан включать `id`: по одному `updated_at` беседы,
  обновлённые в одну миллисекунду, разъезжаются между страницами (тест на это
  есть в `database.test.ts`).
- Фикстуры `createFakeApi` жили в ноябре 2023 (`clock = 1_700_000_000_000`), и
  при окне «текущая неделя» весь список уезжал в «Более старые». Часы фикстур
  переведены на `Date.now()` — иначе DOM-тесты проверяли бы список, который
  реальный пользователь видит свёрнутым.

## Куда занесено

- docs/kb/ui.md — «Индекс бесед грузится по требованию», пагинация недельных
  секций, метки без сводки рана.
- docs/kb/protocol.md — параметры `since`/`beforeAt`/`beforeId`/`limit` и
  `withRuns`.

## Открытые вопросы / что осталось

- `conversations?scope=chat` всё ещё считает `conversationCosts` (агрегат с
  `json_extract` по всем сообщениям) — на окне недели это 25 мс, но на полной
  выдаче было около секунды.
- Остальные пять списков (`make`, `images`, `console`, `web-reader`,
  `playwright-reader`) грузятся вместе с индексом; их можно тянуть при входе в
  соответствующий раздел.
