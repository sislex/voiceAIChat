# release-center-improvement-cycles

Серия из десяти циклов улучшений Release Center по просьбе пользователя: каждый
цикл — десять правок/улучшений, тесты, коммит и PR в `main`. Мобильная версия
проверяется в Storybook (`Releases/ReleaseCenter`, viewport mobile1) и в кадре
390px локальной сборки.

## Цикл 1 — оболочка, форма сборки, мобильные таблицы

1. Сегментный переключатель «Весь проект / Приложения» в общей колонке; починен
   селектор высоты `.toolpage.projpage > .release-shell`.
2. «Настройки» — кнопка в шапке панели, форма лимитов панелью с «Отмена»/«Сохранить»
   и подтверждением «Лимиты сохранены.».
3. Поля формы сборки не выходят за карточку на телефоне.
4. Таблицы релизов и деплоев на ≤720px — карточки с подписями колонок.
5. Релиз в production помечен в списке деплоя, таблицах и «Последнем деплое»;
   подпись «Задеплоить повторно» с пояснением.
6. История деплоев — статусы-пилюли и SHA.
7. Подсказка следующей версии (`suggestNextReleaseVersion`) и кнопка подстановки.
8. Валидация версии под полем: формат и существующая ветка блокируют сборку.
9. Русские подписи статусов шагов ленты, пропущенный шаг отмечен.
10. Живая детальная карточка: тик длительности, метрика машины/production,
    автообновление списка при идущих сборках, точка «идёт» на вкладках.

Проверка: `npm run gate:fast`, сториз через axe, Storybook в мобильном кадре.

## Цикл 2 — сервер деплоя, блокировки, пагинация, GitHub

1. Живой лог health-check каждые 30 с с последним ответом production.
2. Порог свободного диска перед сборкой 5 → 10 ГБ.
3. Подсказка про `/var/log/voicechat-deploy.log` в ошибке health-check.
4. `attempt` и `failure` в сводке релиза; причина ошибки видна в списках и в
   карточке последнего деплоя.
5. «Задеплоить» отключён, пока идёт другой деплой (с пояснением).
6. «Собрать новый релиз» отключён, пока идёт другая сборка.
7. Списки релизов и деплоев — страницами по 20, «Показать ещё (N)».
8. Ссылки на GitHub в деталях: коммит, ветка, сравнение с production (`gitUrl`).
9. Последняя вкладка Release Center запоминается (`vc.releases.tab`).
10. Карточка «Сейчас в production» на вкладке деплоя; строки таблиц — Enter/пробел.

## Что выяснили

- Деплой релиза сбрасывает сессии: браузер и токен `session.json` локальной
  сборки получили 401 после публикации 0.1.301 — для API-проверок нужен новый вход.
- Деплой 0.1.301 первый раз упал на `docker build` browser-runner («failed to
  extract layer») при 91 % занятого диска (5,7 ГБ свободно — выше порога prune
  5 ГБ). Помог `docker builder prune -af` (9,8 ГБ кэша), повторный деплой прошёл.
