# web-reader-action-readiness

## Что сделано

- Актуализация БЗ после фикса цепочки `mcp__browser__open → read/find/click`
  (коммит `7d953e7`, 8 файлов): host `WebReaderHost` теперь очередует DOM-команды
  до готовности страницы, а обобщённый таймаут заменён точной диагностикой.

## Что выяснили (факты, которых не было в KB)

- Живая панель Web Reader — `WebReaderHost`; `PreviewPane`/`WebPreview` больше
  нигде не монтируется (только `WebPreview.dom.test.tsx`), но хранит собственный
  исполнитель действий со своими текстами ошибок — поиск по сообщению уводит в
  неиспользуемый код.
- Готовность приходит от инъецированного скрипта `previewProxy.ts` синхронно при
  выполнении в конце `<body>` (`voicechat.preview.page-ready.v1`), до установки
  его собственного `message`-обработчика; `beforeunload` шлёт `page-loading`,
  `pagehide` снимает обработчики — поэтому read после клика с переходом ждёт
  новую страницу.
- Рекордер не буферизует команды: `run-action` до готовности сразу получает
  отказ «Страница ещё загружается», очередь держит только host. Ошибку загрузки
  рекордер достаёт из same-origin `contentDocument` (`preview_unavailable`,
  поле `message`), `onError` даёт сетевую ошибку.
- Край: повторный `open` того же адреса не меняет prop `url`, iframe не
  перезагружается, нового `ready` нет — вызов падает по 10-секундному таймауту
  «страница всё ещё загружается».
- `npm run -w @voicechat/ui test -- --run src/WebPreview.dom.test.tsx` — 15
  тестов проходят, включая новый блок `WebReaderHost action lifecycle`.

## Куда занесено

- docs/kb/ui.md — разделы «Независимый Веб-рекордер и контракт хоста» и
  «Действия модели в превью (mcp__browser__*)»; заодно исправлено устаревшее имя
  компонента `WebRecorderHost` → `WebReaderHost`.
- docs/kb/server-internals.md — оговорка про `ensurePreview`: гейт остался в
  неиспользуемой `PreviewPane`, живая панель идёт в `/api/preview` без него.
- Статьи «Разработка проекта»: новая — про цепочку `mcp__browser__*`, плюс
  правки в «Веб-превью и авторизация iframe» и «Сплит чата с веб-превью».
