# codex-cumulative-usage

## Что сделано

- Разобран рост «↓ входа» и стоимости у каждого следующего ответа Codex в чате на проде ($85 за беседу при реальных ≈$9).
- `turn.completed.usage` Codex теперь трактуется как накопительный итог треда: сырые числа хранятся в `TurnMeta.codexThreadUsage`, расход хода — разница с предыдущим ответом беседы (`codexTurnUsage`), вход приведён к семантике «без кэша».
- Разовая миграция `migrateCodexThreadUsage` переписала старые ответы Codex (оба бэкенда, идемпотентно); SQL стоимости беседы и отчёта перестал вычитать кэш из входа; CI считает разницу по треду рана.

## Что выяснили (факты, которых не было в KB)

- В `codex exec --json` кадр `turn.completed` берёт `ThreadTokenUsage.total`, а не `.last`; при `resume` итог продолжает расти с прошлых ходов (проверено по исходникам Codex CLI и по цифрам прод-чата).
- Оценка стоимости карточки (`estimateCostUsd`) ждала вход без кэша, а SQL сайдбара вычитал кэш сам — два пути расходились и оба были верны лишь для одного движка.

## Инцидент релиза 0.1.304 (14.09.2026)

- Ядро прода падало heap-OOM через 4 с после старта: миграция читала все ~500 МБ
  меты Codex одним запросом при куче ~512 МБ. Порт 8787 отвечал connection refused,
  остальные контейнеры были живы, `RestartCount` рос.
- Остановка цикла: вручную вставить `app_config('codex_thread_usage_v1', …)`;
  исправление — мета по одному сообщению, ключ `codex_thread_usage_v2`.
