# chat-240-parallel-merge

## Что сделано

- Обязательный гейт и `kb_update` в merge-ране разведены по двум detached
  worktree проверяемого SHA и запускаются одновременно через `Promise.allSettled`.
- Описание merge-рана в БЗ приведено к коду: разделы про amend-коммит БЗ,
  маркер `node_modules/.merge-lock-sha` и одноразовый push в main устарели и
  переписаны.

## Что выяснили (факты, которых не было в KB)

- Оркестрация merge тестируется без git и сети: `CommandExecutor` — `vi.fn`,
  узнающий скрипт по подстроке, `now` — счётчик; тесты фиксируют направление
  коммитов и порядок push, а не только исход.
- Зависимости теперь ставятся в каждом worktree отдельно (общий npm-кэш
  `.merge-npm-cache`), маркера пропуска `npm ci` больше нет.
- Изменившийся `origin/main` перед публикацией не роняет ран, а рекурсивно
  перезапускает `execute` с нового снимка.
- Нормализация `updated:`/`checked:` при разрешении конфликтов тем построчная и
  портит примеры фронтматтера внутри ```-блоков; так `@@KB@@` попал в
  `kb-workflow.md`, пример восстановлен.

## Открытые вопросы / что осталось

- `.github/**` классифицируется как документальный путь и не вызывает полный
  повторный гейт — поведение зафиксировано по коду, обоснованность не проверялась.
