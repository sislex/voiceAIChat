# Журнал сессий

По файлу на сессию/задачу: `<дата>-<машина>-<slug>.md`. Машина берётся из
`hostname` (или `VC_KB_MACHINE`), поэтому агенты на разных машинах никогда не
пишут в один файл — merge-конфликтов в журнале не бывает.

Создать запись:

```bash
npm run kb:log -- добавлен-релей-pty
```

Журнал — **не** источник истины о состоянии кода: устойчивые факты переносятся в
`docs/kb/*.md` или в `AGENTS.md` пакета. Здесь остаётся контекст «что делали, что
выяснили, что осталось» — чтобы следующий агент (или другая машина) продолжил, а
не начинал с нуля.

Читать весь журнал не нужно: смотри последние записи (они в индексе
`docs/kb/README.md`) или ищи по slug.
