# model-api-tool-transit

## Что сделано

- Транзит инструментов для приложений, которые ходят к моделям через API моделей другого Core: приложение (стенд с `VC_CHAT_MODEL_API`) держит исходящий WebSocket к поставщику и заменяет адреса своих MCP-серверов в запросе хода на заглушки `transit:<слот>`; поставщик выдаёт раннеру свои адреса `/mcp/transit/<токен хода>/<слот>` и пересылает HTTP-обмен по сокету приложения, не разбирая содержимое.
- Поставщик запускает такой ход в режиме `toolOnly`: только MCP-инструменты приложения, без команд и файлов раннера. Включается флагом `VC_MODEL_API_TOOL_TRANSIT=true`, по умолчанию выключено.
- Стенд при живом транзите собирает ход Workspace как обычно (свои MCP-серверы и машины), без транзита остаётся текстовым, как раньше.

## Что выяснили (факты, которых не было в KB)

- Раннер уже принимает `toolOnly` вместе со всеми полями MCP-адресов для Claude и Codex; правка раннера не понадобилась.
- Маршруты `/mcp/*` не закрыты общей авторизацией Core (она действует на `/api/`), секретом служит часть адреса — транзитный адрес устроен так же.
- `VC_CHAT_TEXT_ONLY=true` на стенде выключает инструменты независимо от транзита.

## Открытые вопросы / что осталось

- На проде флаг не включён; включение — решение владельца.
- Сессии CLI для таких ходов стенд не продолжает: каждый ход собирается из истории.
