# deploy-prod-current-session

## Что сделано

- Зафиксирован безопасный запуск production-деплоя инструментом `mcp__kb__deploy_prod` из текущего пользовательского хода.
- Метаданные тем дополнены путями серверной регистрации и host-side `DeployTrigger`.

## Что выяснили (факты, которых не было в KB)

- Инструмент не принимает идентификатор пользователя, токен, команду или аргументы: владельца даёт `kbToolBroker`, а роль и блокировка перечитываются из БД непосредственно перед запуском.
- Только актуальный незаблокированный `admin` может вызвать инъектированный `DeployTrigger`; `accepted` и `running` штатны, отказ и недоступность host API возвращаются структурированной MCP-ошибкой без shell-команды.
