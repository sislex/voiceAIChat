# Круг 28: свежая чужая фича хода снова прошла мимо инспектора

Источник находок — интеграционный аудит свежевлитых в main фич. Коммит
`fe892d1b` (вчера) научил ход подключать read-only Make-источники по
`task_designs` связанной задачи — и пункт в снимке не завёл. «Что сможет
модель» в чате задачи снова отвечало неполно, меньше чем через сутки после
завершения большого аудита.

Сделано: пункт `mcp-make-design` (замок `kind`, текст замка расширен на
«привязку задачи»), тест с обеими сторонами (в чате задачи с макетом доступен
и не выключается, в обычном чате — недоступен с честной причиной), живой стенд
показал всю цепочку: автосвязь из фикса CHAT-391 → чат задачи → пункт.

## Вывод

Пока раздел жив, расхождения будут появляться с каждой чужой правкой хода —
их источник не исчерпывается, исчерпалась только моя очередь находок на
сегодня. Дешёвая защита на будущее: перед правкой `turns.ts` смотреть, есть ли
у нового условия пункт в снимке (правило уже в llm.md).

## Чего стоило избегать

**Грязная красная проверка.** Первая попытка (вырезать блок питоном) сломала
файл синтаксически — vitest ответил «no tests», что выглядит как падение, но
ничего не доказывает. Красная проверка обязана менять поведение минимально
(здесь: `available: false`), а не кромсать код.
