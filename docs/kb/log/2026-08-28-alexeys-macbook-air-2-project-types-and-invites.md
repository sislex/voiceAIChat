# project-types-and-invites

Первый шаг большой фичи «типы проектов + приглашения»: снят админский замок с
создания проектов и настроена локальная почта, без которой приглашения нельзя ни
проверить, ни использовать.

## Что сделано

- Полномочие `project:create` доступно любой роли (`ANY_ROLE_PERMISSIONS` в
  `apps/server/src/users/auth.ts`); `POST /api/projects` переведён с
  `project:settings` на него. Создатель по-прежнему садится владельцем, и внутри
  проекта права определяет `isProjectOwner`, а не глобальная роль.
- Убран мёртвый `settingsGuard` из `routes/projects.ts`: настроечные роуты гейтит
  глобальный hook, свой `preHandler` им не нужен.
- Новый `apps/server/src/users/auth.permissions.test.ts` — таблица
  `projectPermissionForRequest` и матрица `hasProjectPermission`; порядок правил
  теперь закреплён тестом.
- Порты dev-режима вынесены в окружение (`apps/web/vite.config.ts`:
  `VC_WEB_PORT`/`VC_API_PORT`/`VC_RECORDER_PORT`), дефолты прежние.
- `scripts/dev-web.sh` читает `.env` из корня.
- Подсказка пустого состояния проектов называла кнопку «+ Проект», хотя в
  сайдбаре она «+ Новый проект» — исправлено вместе с тестом.

## Что выяснили (факты, которых не было в KB)

- **`.env` в dev не читал никто.** Его подхватывает только docker compose; при
  `npm run dev:web` → `tsx watch` переменные почты не действовали, и письма
  молча уходили в лог вместо SMTP. Отсюда же требование кавычек в `.env`:
  файл теперь исполняется шеллом, и `ChatAI <no-reply@…>` без кавычек стал бы
  редиректом.
- **`VC_PUBLIC_URL` указывает на origin интерфейса, а не API.** Ссылка письма —
  hash-маршрут UI, в dev его отдаёт Vite (5273), API проксируется. С портом API
  ссылка из письма не открывается.
- **Vite-прокси dev-клиента был жёстко прибит к 8787**, поэтому второй сеанс
  рядом с чужим молча работал бы с чужим сервером.
- **Открытая регистрация выключена по умолчанию** (`signup.enabled` в
  `app_config`, читает `readSignupConfig`); при выключенной отдаётся 404 с
  текстом «Регистрация закрыта».
- **Прод-`.env` из приложения не изменить, и это защита:** `POST /api/admin/deploy`
  проксируется в host-side сервис с единственным фиксированным `POST /deploy`,
  контейнеру не выданы ни Docker socket, ни `$PROD`, ни root.
- `/api/projects/` со слешем в конце не классифицируется матрицей прав; безопасно
  лишь потому, что Fastify поднят без `ignoreTrailingSlash`.
- Проверено сквозным сценарием в браузере: регистрация по email → письмо в
  Mailpit → ссылка → вход как `developer` → создание своего проекта, роль
  «владелец».

## Открытые вопросы / что осталось

- Части A (дерево типов) и C (приглашения) — по плану, ещё не начаты.
- Реальная доставка через Яндекс ждёт пароль приложения; прод-`.env` — ждёт ssh.
- На машине висят четыре осиротевших dev-сервера (~11 ч), один держит :8799 —
  не мои, не трогал.
