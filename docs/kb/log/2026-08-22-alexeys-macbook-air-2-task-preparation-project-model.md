# Подготовка использует снимок проектной LLM

## Что сделано

- Актуализировано описание выбора и фиксации LLM для подготовки задачи.

## Что выяснили (факты, которых не было в KB)

- Новая попытка проверяет точную effective-пару проекта по deny-list и атомарно сохраняет её в `task_preparation_runs`.
- Первый запрос, correction, продолжение после ответа и recovery используют сохранённую пару без автоматической подмены движка или модели.
- UI больше не предлагает разовый LLM-override и показывает проектную пару до запуска и фактический снимок попытки после запуска.
