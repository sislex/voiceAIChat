# stopped-answer-final-cost

## Что сделано

- API моделей отдаёт состояние запуска по его id: `GET /api/model-runner/v1/run/:id` → `running`, `settling` или `done` с фактическим расходом `costUsd`. Запись учёта хранит публичный id запуска.
- Core стенда после «Стоп» раз в 30 с (до часа) спрашивает это состояние и, когда расход известен, записывает его в остановленный ответ и снимает пометку «досчитывается» (`costPending: false`), рассылая обновлённое сообщение.

## Что выяснили (факты, которых не было в KB)

- Стенд обращается к API моделей прод-Core, поэтому итоговый расход появится на стенде только после выпуска этой версии Core на прод; до этого прод отвечает 404 и пометка остаётся.
