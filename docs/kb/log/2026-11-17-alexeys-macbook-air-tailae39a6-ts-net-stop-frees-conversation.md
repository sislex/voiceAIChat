# stop-frees-conversation

## Что сделано

- На стенде с API моделей (`VC_CHAT_MODEL_API=true`) «Стоп» больше не блокирует беседу: Core забывает тред провайдера, следующий вопрос сразу уходит новым тредом с контекстом из сохранённой истории.
- Остановленный ответ сохраняется с `meta.stopped` и `meta.costPending`; Core UI показывает «Ответ остановлен… расход будет списан по факту».
- Если отказ «тред занят» всё же пришёл, тред забывается и сообщение повторяется один раз на новом треде, а не падает в очереди.

## Что выяснили (факты, которых не было в KB)

- Беседу держала аренда треда Codex в раннере (`rawRun.ts`, `codexThreadLeases`): учтённый запуск держит её до выхода CLI, а API моделей после «Стоп» запуск не гасит. Core стенда возобновлял тот же тред и получал отказ.
- Итоговый расход остановленного запуска Core стенда не получает: поток он уже не читает, отдельного запроса состояния запуска в API моделей нет.

## Открытые вопросы / что осталось

- Обновление сообщения итоговым расходом: нужен запрос состояния запуска в API моделей (сторона прод-Core) и опрос со стороны стенда.
- Публичный платный чат (`chatTextOnly` с учётом) после «Стоп» по-прежнему ставит очередь на паузу до закрытия учёта — не менялось.
