# chat-storage-defects

## Что сделано

- Ходы без инструментов (Chat, Required, текстовое развёртывание, стенд с API моделей): текстовые вложения до 64 КБ (200 КБ на ход) кладутся в промпт содержимым, картинки, двоичные и большие файлы перечисляются с причиной; файлы исполнителю не отправляются (`prompt/inlineAttachments.ts`, `turns.ts`).
- Удалённое хранилище (`fileStorage/remote.ts`): роль admin передаётся заголовком `x-sislexa-role`; оборванная сервисом потоковая загрузка сверх свободной квоты отвечает 413 `quota_exceeded` с `usedBytes` и `limitBytes`; сбой превью — оригинал для картинок до 2 МБ, иначе 501 `preview_unavailable` (новый код в контракте).
- Пространство беседы (`fileStorage/chatSpace.ts`): название равно названию беседы, вложения лежат в `ГГГГ-ММ-ДД/<имя>`, при удалении беседы пространство удаляется.

## Что выяснили (факты, которых не было в KB)

- Сервис хранения закрывает соединение, как только поток превысил квоту, поэтому `fetch` падает без ответа и код 413 терялся (выходил 503 `storage_unavailable`).
- `GET /api/storage/cluster` отвечал admin 403, потому что сервис берёт роль из `x-sislexa-role`, а Core его не слал.
- Пункт «Хранилище» в боковой панели Core UI показывался только в режиме Identity (`App.tsx`, `storageOpenUrl`); манифест `/api/system/applications` отдаёт `storage` с `enabled`, `location: external`, `openUrl`.
- Картинки, сгенерированные моделью в чате, переносятся на машину беседы (`imageRelocate.ts`, каталог `.generated_images` или управляемое хранилище машины); в файловое хранилище они не пишутся. Студия изображений хранит файлы в своём каталоге.

## Открытые вопросы / что осталось

- Ходы с инструментами через API моделей по-прежнему отправляют вложения в теле запроса; большое вложение там может дать 413.
- Сгенерированные картинки в пространство беседы не кладутся.
