# Независимые проверки и релизы приложений

Пользователь попросил определить, что осталось для работы над отделёнными
приложениями с собственными тестами, релизами, deploy и минимальными версиями
зависимостей. Проверены граф гейта, workspace-зависимости, границы Make/Reader,
Dockerfile/Compose и shared/manager-контракт релизов. Во время read-only анализа
рабочий checkout внешним процессом переведён на чистую актуальную main `7b2c3283`;
итоговые выводы сверены на ней.

Выявлена разница между границами процесса, исходников, frontend-сборки и релиза:
сейчас собственный сервис наследует общий Docker build, remote Make импортирует
его runtime в ядро, а legacy App продолжает собирать продуктовые панели вместе.
Модель релизов относится к проекту целиком и не хранит требования к версиям
других приложений. Существующий план Make оставлял независимый выпуск открытым.

Факты внесены в docs/kb/features/releases.md. План, последовательность внедрения,
политика тестов, требования к совместимости/откату и критерии готовности —
docs/plans/application-independent-releases.md. Первый пилот — backend Make;
переход UI выделен явно, чтобы не считать отдельный backend полным отделением.

В этом шаге подготовлены документация и план; код гейтов и релизов не менялся.
Проверки: git diff --check, генерация KB-индекса и gate:fast для документации.
Результат последнего означает отсутствие затронутого кода, а не прогон тестов
приложений. Публикация, deploy и новые коммиты не выполнялись.
