# Задача из Make-чата: автосвязь макета и файлы для подготовки

Случай CHAT-391: задача про макет Make «Проект 14» блокировала подготовку
вопросом «критичный источник истины недоступен» — модель пыталась открыть
опубликованную страницу по URL из описания, а связи `task_designs` у задачи
не было, поэтому инструменты `make_*` в ран не попадали.

Сделано:
- `sourceConversationId` в `tasks:create` и `tasks:createFromProposalInPreparation`;
  сервер сам линкует whole_project, если источник — Make-чат этого проекта;
- связь ставится до запуска подготовки (makeSources собираются при старте рана);
- `preparationDesignNote` в промпте подготовки: инструменты по имени и прямой
  запрет искать опубликованную страницу по URL;
- интеграционный тест с мок-CLI перехватывает LlmRequest подготовки; обе
  половины проверены падением без починки.

## Ограничения проверки

Реальный ран подготовки на локальном стенде не запускается: свежий CLI-профиль
не авторизован («Not logged in — run /login»). Живой прогон CHAT-391 возможен
только на проде после релиза. Ручной обход для существующей задачи доступен
уже сейчас: карточка → «Дизайн» → «Связать дизайн» → выбрать Make-проект →
перезапустить подготовку (хинт раннера о make-источнике работает и без релиза).

## Попутные факты

- Виджет task-launch не открывается в Make-чатах вовсе: `inChat` ложен на
  `/make/:id`, а подсказка taskLaunch отфильтрована видом чата — задачи о
  макетах создаются с доски или ассистентом, поэтому автосвязь по
  `sourceConversationId` нужна и там, где источник — обычный чат проекта.
- Подготовка требует ровно одну колонку `preparation` и стартует переносом
  карточки в неё; машина не обязательна (executionDisabled).
