# Независимые проверки и выпуски приложений

## Что сделано

- Реализованы каталог владельцев и готовности, отдельные release/API/data версии,
  минимальные и верхние границы зависимостей, capabilities, проверка будущего
  состава и обратных ограничений. Runtime metadata сверяется с immutable digest.
- `make-contracts` отделён от runtime; гейты работают по приложению, публичному
  контракту или фактическому графу библиотек. Lock diff учитывает обе версии,
  nested/peer/optional зависимости. Неизвестные пути включают общий гейт с E2E.
  CI, merge runner, legacy release, AGENTS и conventions используют новые команды.
- Изолированные Docker-контексты и реальные контрактные driver для Make, Image
  Studio, Reader API, Chromium, LLM, STT, TTS и четырёх UI-приложений. Сборка включает
  только нужное npm-замыкание и очищенный lock; `.env` и локальные артефакты исключены.
- Добавлены компонентные таблицы, миграция старой файловой БД, durable lock/CAS,
  идемпотентность, подготовка точного SHA, матрица артефактов, REST/IPC и Release
  Center. Deploy меняет только выбранные сервисы без build/deps, проверяет реальные
  связи и остальные container ID. Rollback использует предыдущий digest; неизвестное
  состояние сохраняет блокировку. Смена target останавливает restart reconcile.
- Make/MakeSharedView, Image Studio и Playwright Reader с тестами/стилями вынесены
  из UI; Web Reader также имеет отдельный артефакт. Общая библиотека ui-foundation
  содержит редакторы, frame и примитивы. Реальный App web/desktop загружает панели
  через manifest/SRI и версию host API, изолирует ошибки загрузки/рендера, сохраняет
  старые assets для открытых вкладок и поздней загрузки Monaco. UI-выпуск требует
  версии backend и core, а матрица выполняет его через собранный host baseline.
- Добавлены пример Compose и настройки площадки. `core --baseline` сохраняет
  полный web/embedded host для начального перехода, включает обратные требования
  ко всем опциональным сервисам. После adoption production-состава старый общий
  deploy заблокирован; legacy-подготовки и история остаются доступны.
- Исправлен существующий Angular-шаблон Make: Zone.js загружается до standalone
  bootstrap. Реальные Chromium-тесты получили достаточный функциональный таймаут
  вместо проверки скорости 200 мс под параллельной нагрузкой. E2E Reader использует
  публичный экспорт shared и ждёт холодную загрузку host явно; E2E poll
  ограничен 10 с для нескольких HTTP/Chromium-переходов. DOM-тест HTTP Reader
  завершает passive effects первого mount до имитации навигации iframe. Сохранение сценария
  принадлежит host, его вспомогательный runtime-импорт из Reader устранён.

## Проверки и реальные пилоты

- Скриптовые проверки build/gate/deploy/матрицы/связей: 30 тестов прошли.
  Старые тесты инструментария также прошли. Shared release/frontend — 17 тестов;
  адресные DB/legacy tests после interop guard — 32; manager — 6; REST — 3;
  DOM Release Center — 5; host — 4; gateway — 2. Миграция проверялась на файле
  старой БД, включая сохранение истории и блокировки после повторного открытия.
- Desktop typecheck и настоящая Electron renderer-сборка прошли. Браузерные
  сценарии панелей и Release Center запускались в Chromium; скриншоты desktop
  и mobile просмотрены. Отдельно проверен Make UI через `file://` desktop.
- Make 1.0.0 → 1.1.0 проверен на историческом бизнес-коде исходного HEAD и текущем
  ядре. Историческому стенду добавлен только адаптер health metadata. Версии
  синтетические, образы development из рабочего дерева; registry был локальным.
  Это не production-релизы и не доказательство совместимости с выдуманным
  опубликованным baseline.
- В обоих backend-пилотах прошли реальный RPC, обновление Make при неизменных
  container ID ядра/контрольного сервиса, сохранность файла в томе, намеренный
  неверный секрет кандидата, автоматическое восстановление и явный rollback.
- UI-пилот использовал полный собранный web-host: Make UI 1.0.0 → 1.1.0 и rollback.
  Container ID ядра и Make, SHA256 bundle оболочки не изменились. Открытая вкладка
  получила прежние hashed assets и поздно загрузила Monaco; reload загрузил новую
  версию. Ошибок страницы Chromium не было. Дополнительно все четыре UI-driver
  прошли через полный baseline-host из Docker. Исторический host без gateway
  отклонён; это проверено отрицательным Docker-сценарием.
- Native-контракты выполнены в отдельных Docker-контейнерах. LLM проверял CLI и
  HTTP, STT — Whisper/модели/WS, TTS действительно синтезировал WAV. Внешняя
  авторизация CLI и STT-распознавание со скачанной моделью в этот smoke не входят.
- Итоговый `npm run gate:fast` завершился с кодом 0. Из-за изменения общей
  инфраструктуры выбран полный `gate:all`, затем все четыре каталожных E2E:
  typecheck всех workspace, 8440 тестов пакетов (45 штатных skip), 87 тестов
  инструментов, четыре frontend-сборки, web, Storybook и 44 Chromium E2E прошли.
  Последние E2E заняли 39,54 с. Desktop дополнительно прошёл typecheck и build
  после последней правки runtime-границы. `git diff --check` чистый.
  Ранее красные прогоны не учитывались как успешные: исправлены iframe deadline,
  публичный импорт E2E, ожидания холодного browser-host и passive effects DOM-стенда.


## Что выяснили и куда занесено

- Удаление workspace из package.json не очищает lock: нужен транзитивный обход
  записей со ссылками всех выбранных workspace. Зафиксировано в releases.md.
- Потеря команды агента не доказывает завершение deploy: reconcile проверяет PID
  владельца файловой блокировки. DB guard также не допускает гонку со старым
  глобальным production deploy. Зафиксировано в releases.md.
- Разделения React-кода недостаточно: нужны host ABI, отдельный manifest и старые
  assets, а worker должен разрешать URL относительно артефакта, включая file://.
  Зафиксировано в ui.md и AGENTS панелей/ui-foundation.
- Актуализированы тематические пути после переноса UI: projects, machines,
  protocol, feature-preview, playwright-reader. План отражает реальные границы.

## Оставшиеся ограничения

- Шаг 7 закрыт для работоспособных standalone-приложений. У automation-runner
  исходный executor всё ещё возвращает `executor_adapter_not_configured`, deploy
  намеренно запрещён. Встроенные Web Reader API, канбан, админка, машины, core/web
  и клиентские дистрибутивы не объявлены независимыми. Нужна отдельная граница их
  процессов/данных; для automation — настоящий исполнитель.
- Перед первым настоящим выпуском площадке нужны собственные baseline digest,
  registry, секреты/тома и release-matrix.json на действительных артефактах.
  Production не менялся. Git-публикация выполняется отдельным шагом по просьбе
  пользователя. Временные стенды пилотов удалены;
  Docker Desktop оставлен работающим, пользовательские контейнеры не менялись.
