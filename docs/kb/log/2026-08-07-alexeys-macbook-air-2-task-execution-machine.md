# task-execution-machine

## Что сделано

Карточка задачи получила необязательную машину выполнения. Её выбор проходит через
общий контракт, REST и IPC, SQLite и настройки CI; при запуске ран берёт машину
карточки, а при пустом значении — машину проекта по умолчанию.

## Что выяснили (факты, которых не было в KB)

`agent_id` у старых задач намеренно остаётся `NULL`, поэтому миграция не меняет их
маршрут выполнения. Машину можно сохранить только если она привязана к тому же
проекту; перед запуском эта связь проверяется повторно. Отвязанная машина и
отсутствующий project default не запускают ран. Фолбэк на другую онлайн-машину,
включая приоритет свободной, этим изменением не реализован.

## Открытые вопросы / что осталось

Для требований об автоматическом выборе доступной машины нужны отдельные правила
планирования и проверка статуса машин до старта; текущий выбор является явной
привязкой задачи.
