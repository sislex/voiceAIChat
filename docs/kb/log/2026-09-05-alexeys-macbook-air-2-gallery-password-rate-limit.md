# gallery-password-rate-limit

## Что сделано

Итерация 68 студии картинок (8 пунктов, один из них — дыра в защите): пароль
публичной галереи больше не перебирается без счёта, поле пароля названо для
читалки на обеих публичных страницах. Три теста (лимит попыток, подпись поля,
плюс уже существовавшие), проверка живьём curl'ом.

## Что выяснили (факты, которых не было в KB)

- **`/g/:token/__auth__` не считал попытки.** У публичного превью Make тот же
  сценарий давно закрыт `SlidingWindowLimiter`, у галереи — нет: пароль можно
  было подбирать сколько угодно. Лимитер переиспользован как есть
  (`apps/server/src/make/rateLimit.ts`), ключ — «IP + токен», окно 10/10 минут.
- Счёт идёт по **попыткам**, а не по промахам: в заблокированном окне верный
  пароль тоже ждёт. Это осознанно — иначе окно обнуляется угадыванием.
- Поле пароля на публичных страницах было подписано только `placeholder`,
  который читалка подписью не считает. Правило пакета про `aria-label`
  распространяется и на серверные HTML-страницы, а не только на React.
- Проверка без находок: ссылка на кадр (`#/images/<conv>/<file>`) открывает
  лайтбокс на нужном файле — «кадр-005.png · 7 из 90».

## Открытые вопросы / что осталось

- Лимитер живёт в памяти процесса: после перезапуска сервера счёт начинается
  заново. Для публичной галереи этого достаточно, но если появится кластер —
  придётся выносить в общее хранилище.
