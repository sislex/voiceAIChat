# context-inspector-round-10

## Что сделано

1. Политика машины в её карточке: каталоги, паттерны команд, правка файлов,
   сеть, число навыков.
2. `cliMcpServers` в снимке — список MCP-серверов, как его печатает движок.
3. Предупреждение `problem`, когда выключены проект, БЗ и персонализация вместе.
4. Статус «Выключено в настройках» отдельно от «Не настроено».
5. Фильтр по группе источников.
6. Счётчик выключений в истории конкретного источника.
7. Ссылка на вкладку контекста целиком.
8. Тесты сервера: политика в снимке, предупреждение «вслепую».
9. Тест UI: фильтр по группе, MCP движка, новый статус.
10. KB: разбор круга в ui.md.

## Что выяснили (факты, которых не было в KB)

- `AgentPolicy` называет поля `allowedDirs`, `denyPatterns`, `allowPatterns`,
  `allowWrite`, `allowNetwork` (не `directories`/`denyCommands`, как можно
  предположить по смыслу), а версии агента в `AgentRecord` нет — она приходит
  только в живом `AgentInfo` из реестра.
- В фабрике снимка `ConversationSettings.dom.test.tsx` всего одна группа
  (`instructions`), поэтому тест фильтра по группам нельзя писать «на глаз» по
  идентификаторам из `fakeApi` — там набор другой. Отладка через вывод опций
  селекта заняла минуту и сэкономила круг догадок.

- Ссылка «на вкладку контекста» не работала: `parseChatRoute` не понимал
  `/chat/:id/context` (три сегмента) и возвращал `null`, поэтому окно настроек
  не открывалось. Добавлен вид маршрута `context-tab`; `ConversationSettings`
  сверяет префикс без хвостового слэша. Нашлось только в браузере — тесты
  проверяли переход, но не сам адрес.
