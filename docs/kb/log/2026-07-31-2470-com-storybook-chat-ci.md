# storybook-chat-ci

## Что сделано

- Общие фикстуры домена `packages/ui/src/test/fixtures/`: `chat.ts` (сообщения,
  активность хода со смещениями `at`, `TurnMeta`, образцы markdown, стрим),
  `ci.ts` (команды, раны, шаги, лог, паузы, авто-фикс, метрики + готовые сценарии
  `RunFeedCache`: очередь / выполняется / упал / успех / авто-фикс / ждёт ответа /
  гейт плана), `machines.ts` (телеметрия, парк машин, `MachineOps`, фейковый PTY,
  картинка-SVG в base64), `conversations.ts` (полный `Conversation`).
- Сториз чата (`Chat/*`): `MessageTimeline`, `MessageActivity`, `MessageMeta`,
  `MessageImage`, `Markdown`, `VoiceBar`, `ChatColumn`. Сториз CI (`CI/*`):
  `RunFeed` (переписан на общие фикстуры), `CiCommands`, `CiConsole`,
  `CiTaskSettings`, `CiSlotEditor`. Сториз машин (`Machines/*`): `AgentCard`,
  `MachineStatus`, `MachineUtility`. Итого 140 новых сториз, минимум по 3 (обычно
  6–14) состояния на компонент.
- Декоратор мостов `src/test/storyBridges.tsx` (`withBridges`): `window.api/ci/fs/
  files/agents/pty` из тех же фейков, что в dom-тестах, с `setup`-колбэком для
  засева (команды справочника, строки лога, подмена `consoleExec`).
- `play`-функции у 24 сториз (`@storybook/test`), в том числе просимые пять:
  раскрытие шага рана, ответ на вопрос модели, отправка сообщения, правка
  сообщения, панель «что ушло модели».
- Семь dom-тестов переведены на общие фикстуры, локальные дубли удалены:
  `ChatColumn`, `ConversationSettings`, `MachineStatus`, `MessageActivity`,
  `MessageMeta`, `MessageTimeline`, `ci/RunFeed`.
- Смоук-сборка витрины стала шагом гейта репозитория: корневой скрипт
  `build:storybook` внутри `npm run verify`.

## Что выяснили (факты, которых не было в KB)

- **Мосты в сториз нельзя ставить из эффекта декоратора.** Эффекты родителя
  выполняются ПОСЛЕ дочерних, а экраны (`CiConsole`, `CiTaskSettings`) дергают
  `window.ci` из своих `useEffect` — они успевали увидеть пустой мост. Рабочий
  вариант: инициализатор `useState` (срабатывает во время рендера родителя).
- **ANSI-последовательности в логе не разбираются нигде** — ни `CiConsole`, ни
  лента шага не интерпретируют `[32m…`, поэтому цветной вывод `npm`/`vitest`
  читается хуже обычного. Зафиксировано сториз `CI/CiConsole → AnsiColors`.
- `btoa` в фикстуре картинки падал `InvalidCharacterError`: подпись графика
  кириллическая, а `btoa` умеет только latin1 — нужен проход через `TextEncoder`.
- Полная витрина проверена headless-браузером (playwright над `storybook-static`):
  244 сториз доигрывают до `completed` и **не делают ни одного запроса за пределы
  витрины**. На этой проверке нашлись четыре реально падавших `play`: результат
  копирования появляется асинхронно (нужен `waitFor`), `activity-brief` в ответе
  с чередованием не один (`getAllBy*`), имя файла в проводнике лежит в кнопке
  вместе с иконкой (искать по `aria-label` «Скачать …»), а вложенный вызов команды
  модели виден только после раскрытия родительского шага «Работа модели».
- Полный `vitest run` пакета UI под параллелизмом ведёт себя как серверный: висит.
  Прогонять файлами/пачками или с `--no-file-parallelism`.

## Куда занесено

- `docs/kb/ui.md` — раздел «Витрина Storybook» (фикстуры, мосты, play, смоук).
- `docs/kb/testing-operations.md` — матрица проверок: `build:storybook` при правке
  сториз/фикстур.
- `packages/ui/AGENTS.md` — правило «данные теста и сториз — одни фикстуры»,
  список сториз чата/CI/машин, `withBridges`, ловушки `play`.

## Открытые вопросы / что осталось

- Разобрать ANSI в логе рана (парсер + классы цвета) — сториз под это уже есть.
- Смоук-сборка витрины пока не заведена командой CI-справочника (команды хранятся
  в БД, из репозитория их не добавить): в репозитории есть `npm run build:storybook`,
  команду раннера нужно создать через UI «Команды».
- Прогон `play`-функций в CI (`@storybook/test-runner` не установлен) — сейчас это
  разовая проверка headless-браузером.
