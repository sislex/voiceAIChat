# chat-model-defects

## Что сделано

- В метаданные хода Claude добавлено поле `resolvedModel` — настоящая модель из события `system/init`, а при единственной не-вспомогательной модели в `modelUsage` итогового события — она. `meta.model` по-прежнему хранит выбранный псевдоним.
- Выход из режима Required теперь очищает список выключенных блоков на сервере: снятие маркера `required-only` убирает и всё остальное, что было записано при включении Required. Настройки чата и копирование контекста применяют маркер первым.
- Пункт `default` в списке моделей Claude называется «Default (Fable 5.2)» с подсказкой `Fable 5.2`; псевдоним `default` оценивается по цене Fable 5.2.
- Смена провайдера внутри беседы: поведение оставлено как есть, закреплено тестом для обоих путей (API моделей и прямой раннер).

## Что выяснили (факты, которых не было в KB)

- Переход Required → Chat целиком выполняет клиент (`sislexa-core-ui`, `packages/ui/src/modules/shell/App.tsx`, `applyContextConfiguration`): он выключает блоки по одному, а обратно включает только те, что есть в новом снимке контекста. Снимок режима Chat короче снимка Required, поэтому 22 блока оставались выключенными.
- У беседы один слот сессии (`claudeSessionId` с префиксом провайдера). Ход Claude перезаписывает его, поэтому следующий ход Codex всегда начинает новую нить с полной историей — одинаково на стенде с API моделей и через прямой раннер. Возобновлять старую нить Codex нельзя: она не видела промежуточных ходов другой модели и потеряла бы их из контекста.
- Кэш на таком ходе при прямом раннере — это префиксный кэш провайдера, а не возобновлённая нить; кэш OpenAI к тому же раздельный по моделям.
- Событие `result` потока Claude содержит `modelUsage` с ключами настоящих моделей; вспомогательные вызовы CLI идут на Haiku.

## Куда занесено

- docs/kb/llm.md — раздел «Real model of a turn, `default` alias, Required exit, provider switch (2026-11-18)» и подпись пункта `default` в описании списка моделей.

## Открытые вопросы / что осталось

- Интерфейс (`sislexa-core-ui`) пока не показывает `resolvedModel`; поле уже приходит в метаданных сообщения.
- Почему на стенде с API моделей у хода Codex нулевое чтение кэша при тех же входных токенах — по коду ядра не объясняется, нужно сравнить сырые события `turn.completed` раннера на обоих путях.
- Возобновление нити Codex после хода другого провайдера потребует отдельного слота нити на провайдера, отметки последнего увиденного сообщения и догоняющего запроса с пропущенными ходами; не делалось.
- Набор выключенных блоков, который был у беседы до выбора Required, не восстанавливается: клиент перезаписывает его до установки маркера.
