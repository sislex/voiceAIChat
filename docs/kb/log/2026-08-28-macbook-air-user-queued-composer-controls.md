# queued-composer-controls

## Что сделано

- Актуализировано описание отправки во время активного ответа и визуального контракта кнопок композера.

## Что выяснили (факты, которых не было в KB)

- Клиент атомарно держит одну неподтверждённую отправку, показывает её в оптимистичной очереди и восстанавливает содержимое при ошибке.
- Сервер идемпотентно сериализует реплики по `messageId`; done/stop продвигают FIFO, ошибка исполнителя ставит очередь на паузу.
