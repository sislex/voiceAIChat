Обнови базу знаний проекта по итогам этой сессии. Правила ведения — `docs/kb/kb-workflow.md`.

Контекст:

- Незакоммиченные изменения: !`git status --short`
- Последние коммиты: !`git log --oneline -5`
- Состояние KB: !`npm run --silent kb:check`

Дополнительная тема от пользователя (может быть пустой): $ARGUMENTS

Порядок действий:

1. **Определи, что достойно KB.** Заноси только устойчивые факты: изменившееся
   поведение, новый контракт/роут/WS-сообщение, грабли и неочевидные причины
   решений, новые команды и переменные окружения. Не заноси: пересказ диффа,
   планы на будущее, разовые детали отладки, то, что и так видно в коде.
   Если заносить нечего — скажи об этом и остановись, не создавай пустых записей.

2. **Выбери место.** Общесистемный факт → соответствующий файл `docs/kb/*.md`
   (`architecture`, `protocol`, `llm`, `stt-tts`, `machines`, `data-auth`,
   `deploy`, `conventions`). Факт про один пакет → `AGENTS.md` этого пакета.
   Факт, важный для каждой сессии (команда, карта, запрет) → корневой `AGENTS.md`,
   но только если он действительно нужен всем: этот файл читается всегда и должен
   остаться коротким. Новая крупная подсистема → новый файл в `docs/kb/` + строка в
   таблице указателей корневого `AGENTS.md`.

3. **Правь по месту.** Встраивай факт в подходящий абзац по смыслу, не приписывай
   списком в конец файла (растущий хвост — источник merge-конфликтов у
   параллельных агентов). Не дублируй код — ссылайся на файл-источник. Если файл
   отмечен в `kb:check` как устаревший и ты работал именно в его `areas` — сверь
   его содержимое с кодом целиком, а не только свою правку.

4. **Обнови даты и метаданные.** Для каждого изменённого файла темы:
   `node scripts/kb.mjs touch <файл>`. Если появился новый источник истины по теме —
   допиши путь в `areas:` фронтматтера.

5. **Запись журнала.** `npm run kb:log -- <короткий-slug>` и заполни созданный
   файл: что сделано, что выяснили, куда занесли, что осталось открытым. Slug —
   по сути задачи, латиницей или кириллицей, без дат (дата и машина попадут в имя
   файла сами).

6. **Проверка.** `npm run kb:index`, затем `npm run kb:check` — не должно остаться
   битых ссылок и неожиданно устаревших тем.

7. **Итог.** Коротко перечисли пользователю, какие файлы изменил и какие факты
   зафиксировал. Изменения не коммить — их коммитит пользователь вместе с кодом
   (или попроси разрешения, если он просил коммитить сам).
